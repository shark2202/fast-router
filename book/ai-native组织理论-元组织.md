## 第一章 定位：元组织是什么

### 1.1 元回答

构建组织的最优路径不存在，存在的是**最优元策略**：**生成（探索）+ 门控（词典序判定：先挡死再优化）+ 收敛（反馈缩小空间）**。组织不是被设计出来的，是被生成和筛选出来的。元组织不"设计组织"——它**运营生成与筛选的过程**。

### 1.2 组织身份与元组织的选择

组织有四重身份：**固化**（执行结构的制度化）、**缓存**（成功协作模式的沉淀）、**筛选池**（对 Actor 的筛选）、**生成器**（新组织的形成能力）。元组织把「**生成器 + 缓存**」两种身份常设化，把「筛选池」职能归入门控组件，把「固化」完全留给临时子组织。

### 1.3 常设与临时的边界

理论明文：**永久存在的是治理能力与组织能力，不一定永久存在的是具体执行结构**。因此元组织常设的只有：治理席位、角色模板、缓存、门禁、学习引擎——**没有执行层，没有一个常设执行岗位**。所有子组织按目标成军、验收即解散；判定类角色（verifier / 敌意审查员）必须每次新开无共享上下文的实例，禁止累积上下文的常设审查员（独立性要求）。

### 1.4 不是什么（负例）

- 不是永久大部门（无常设执行岗位，无科层）；
- 不是"全自动无人组织工厂"（终审、Purpose、不可逆决策永远在人类）;
- 不是模板库越全越好（缓存判据是命中率与保鲜，不是数量）。

## 第三章 Goal 治理（元组织自身的 Locked Goal）

**Goal：对经人类委托进入的任意新目标 G，可靠地产出一个按本规范实例化、经门控、带学习闭环的临时子组织 O=F(G,…)，并使历次成军成本递减。**

**可判定验收条件（AC，每条缺一不算完成）**：
1. 成军前查重通过（注册表内无在航同目标组织）；
2. DecisionRecord 三问事前落盘（含事前预测）；
3. 子组织 AOOS 落盘（含政策继承块、降级拓扑默认节、人类终审栏）；
4. 试点先行（有批量的任务先跑试点批次）；
5. 学习闭环闭合：事后校准回填 + 缓存固化或显式"不固化"留痕 + 成本三字段已记。

**负例（做了不算达成）**：产出仅对话结论不落盘；跳过人类终审直接执行；全量铺开未过试点；学习环节只有总结无行为改变。

**优先级**：正确性 > 判断带宽节约 > 成军速度。

## 第四章 六大组件

每个组件回答两问：使成军流程哪一步**变便宜**？哪个**已发生的死法**因此被消解？

### C1 目标闸（成军前台）
三问过目标（Type III 检查：先确认目标本身值得做）→ 目标锁定三件套（可判定 AC + 负例 + 优先级）→ **成军前查重**（读注册表，防同目标双组织）→ **轻量通道初判**（单 actor 可完成 + 零外部副作用 + 完全可逆 → 免全量成军）。两处硬约束：①分类结论**经 goal-keeper 确认**后方可走轻量路径——判定者不得自免审；②目标闸落盘强制记录**目标进入时间戳**（成本计量起点）。
*变便宜*：目标治理从每次手搓变 checklist。*消解*：同目标双组织事故；元组织自我膨胀。

### C2 成军缓存（三层）
- **pattern 层**：跨组织复用的经验协议（如"引用外部材料必须抓取核实，禁止凭记忆"）；
- **政策层**：子组织 AOOS 自动继承的政策块（§6.1）；
- **构件层**：参数化 AOOS 模板、任务书格式、验证器默认行为、角色四要素模板。
读写协议：成军官单写、子组织只读；**固化双门**——同类经验第二次独立复现，或无共享上下文审查通过，方可 candidate→active（active 化裁决权在 goal-keeper）；**冲突检查**——固化前做同域条目冲突检查；**保鲜**——每条带复验条件与有效期。
*变便宜*：组建成本大头；缓存命中即短路组织形成。*消解*：同类问题第二次交学费。

### C3 生成器（Formation Engine）
**目标路由器**（决策表 §5.2）+ **参数化 AOOS 模板**（§10.1）+ **角色构件库**（§10.3，九角色四要素）。
*变便宜*：从每次从零设计变为参数化实例化。*消解*：漏定义权限/约束类事故。

### C4 门控（Quality Gates）
DecisionRecord 门（状态机）／**敌意审查门**（无共享上下文攻击组织设计与产出；中大型组织必设）／试点门（试点教训回灌任务书后方可全量）／**编排者失效预演**（DecisionRecord 死法栏必含"协调者自身失效"项——协调者重建的"原文"失真曾污染下游，是最重的历史事故）／多样性与委托图审计。
*变便宜*：审设计比审执行便宜一个数量级。*消解*：快照失真、设计者盲区。

### C5 治理层（常设部分）
**不可委托内核**（goal-keeper：终审、Purpose、不可逆决策、解释义务、规范变更、轻量通道分类确认、缓存 active 化裁决、fresh 判定者派发确认）；**政策继承块**（§6.1 自动下传）；**验证额度**（信任三段制）；**判断带宽总账**（多子组织并行时监督负载合并记账，超限先降并发再降标准）；**带宽工程六招一红线**（v0.1.2 增）：带宽分配给基准而非细节（三个压缩器：可执行判据压无限验证/不变量压整类状态/差异矩阵压全部方案）＋六招（浓度分层：可逆×内部给 AI；基准化压缩：人进场前先压战场；判定代表制：细节对抗交 fresh 判别实例，人只收裁决请求；信任额度化；决策界面结构化：上浮必是选择题带后果与可逆性标注；节奏解耦：冻结窗口+里程碑批量+超限 Safe Halt 不降标准）＋一红线（**委托执行不委托判断力维持**——认知债对策：不可逆亲自推演/关键抽样保留人亲自份额/三问先行/撤脚手架演练）。
*消解*：治理链因组织临时而漂移；终审成本随规模线性上升。

### C6 学习引擎（Learning Engine）
**校准**（DecisionRecord 事后回填：预测×结果×意外）→ **三层固化管道**（按经验性质分流进 C2 三层）→ **成军成本记账**（三字段：成军耗时/缓存复用构件数/本次新固化数）→ **注册表同步**（批准即登记、解散即补记）。
**双账本制**（v0.1.1 增，依据 Dream-RSI arXiv:2609.14858 §5.1 受控证据"回放模拟器用法 > 语义 guidance 用法"）：固化产出分两层且互不可替代——**蒸馏层**（patterns/协议文本，服务下次快，但语义归纳偏置会过度约束）与**回放层**（运行记录/DecisionRecord 事后校准，保留分支结构，支持反事实评估"如果当时走了没走的路"）；历史一旦只以摘要形态存在，反事实评估即失效。学习引擎须同时维护两层，禁止用蒸馏层覆盖回放层；回放评估出不了自产分布，定期以外部判别器（fresh 审查/异模型复核）打破回声。
*消解*："知道但没固化"的漏项；"成本递减"不可观测；固化过度（只留摘要丢轨迹）。

## 第五章 运行时

### 5.1 双层循环

**外层（常设，成军官主循环）：**

```
目标 G 进入（仅经 goal-keeper 委托；C1 落盘记录进入时间戳）
 → C1 目标闸：三问过目标 / 查重 / 轻量通道初判
 ├─ 轻量通道：goal-keeper 确认分类 → 单 actor + checklist + 照常登记 + 校准 → 结束
 └─ 全量通道：
    C2 缓存查询 ─ 命中 → 模板实例化（短路）
                └ 未命中 → C3 路由生成 AOOS 草案
    → C4 门控：DecisionRecord 事前 / 敌意审查组织设计 / 试点设计
    → goal-keeper 批准成军 → 批准即登记注册表
    → 子组织运行（内层）
    → Verify（fresh verifier；结论只构成 Pre-Verified，Verified 由人授）
    → C6 校准回填 + 固化（双门）+ 三字段记账
    → 子组织解散 → 缓存增值 → ↺
```

**内层（临时子组织）**：标准 AOOS 循环（Goal→分析→选人→授权→执行→验证→学习→重构）。成军官只持**治理钩子**——例外路由（异常上浮）、验证额度、安全停机——不干预 HOW。

**停摆规则**：goal-keeper 不在线 = 循环停于待批（注册表 PENDING 行）；停摆即安全停机，**无超时自动越权**。

### 5.2 最小路由决策表 v0.1（状态：candidate，首次实测后重估）

| 目标性质 | 通道/组织形态 | 关键门 |
|---|---|---|
| 单 actor 可完成、零外部副作用、完全可逆 | 轻量通道（须人确认分类） | checklist + 登记 + 校准 |
| 批量知识生产（N 项同类） | N 个 researcher 两波派发 + 试点先行 + fresh verifier | 试点教训回灌后方可全量 |
| 理论/规范/设计审查 | fresh 审查员各领一维 + 单接口产物汇总 | 独立判定；判决三选一 |
| 涉及不可逆写入（移动/删除/改既有文件） | 单写者 + 依赖分析前置 + verifier 自写脚本 | 试点先行；全程可逆操作 |
| 涉及核心规范/根本文件 | 只产提案不改本体 | 人类终审前置 |
| 外部抓取型 | 降级拓扑预置 + 禁止凭记忆引用 | 截断显式标注 |

### 5.3 会话自举协议

成军官每次会话开始按固定清单恢复状态，**不依赖记忆**：
①注册表（在航/待批组织）；②缓存库（三层条目状态）；③本规范（版本与政策块）；④最近一次成军的 DecisionRecord 未闭合项。
本规范一切"自动"条款均指**会话内 checklist 强制项**——本体系不要求守护进程。

### 5.4 人类触点（goal-keeper 全部出场时刻，仅四个）

| 触点 | 做什么 | 为什么不能省 |
|---|---|---|
| 通道分类确认 | 确认"轻量/全量" | 防判定者自免审 |
| 批准成军 | 过目 AOOS 与 DecisionRecord | 组织形成是治理节点 |
| 例外与停机 | 处理升级上报 | 停止优先于假验证 |
| 终审授 Verified | 接受/否决交付 | AI 结论只构成 Pre-Verified |

## 第六章 治理

### 6.1 政策继承块（所有子组织自动继承，子 AOOS 不得删除）

**基础纪律**（任何环境通用）：三问决策前置（禁仅按预期收益判断）；一切产出落盘，不落盘不算完成；先想清楚再动手（不确定就问、多解并列、遇矛盾停下）；只改该改的；定好目标再跑（把"做 X"变成"做完 X 后验证 Y"）；禁止不可逆的破坏性操作（除非显式要求）。

**成军局级政策**：

```yaml
policies:
  - id: dedup-before-formation        # 消解：同目标双组织事故
    forbidden: [未查注册表即成军]
  - id: classification-confirmed      # 判定者不得自免审
    required: [轻量通道分类结论经 goal-keeper 确认后方可执行]
  - id: pilot-before-scale            # 消解：全量踩全坑
    forbidden: [有批量任务未过试点即全量铺开]
  - id: no-memory-citation
    forbidden: [凭记忆引用外部材料而不抓取核实]
  - id: degraded-topology-default     # AOOS 模板默认节
    required: [每个子 AOOS 必须预置限流/过滤/超界三类降级拓扑]
  - id: halt-not-silent               # 消解：停机条件满足却被静默跳过的事故
    forbidden: [停机触发条件满足而不留痕上报]
  - id: existence-claims-timestamped  # 消解："运行中事实变化"击穿
    required: [存在性断言必须标注读取时点]
  - id: orchestrator-failure-drill    # 消解：快照失真事故；对本组织自身同样适用
    required: [DecisionRecord 死法栏必含"协调者自身失效"预演]
  - id: cache-solidify-double-gate    # 防学习污染
    required: [缓存固化须满足 第二次独立复现 或 fresh 审查通过，且 active 化裁决在 goal-keeper]
  - id: cache-conflict-check
    required: [固化前须做同域条目冲突检查]
  - id: sampling-rate-explicit        # 信任三段制第三段
    required: [验证额度抽样率显式设定，禁止"感觉还行"]
  - id: registry-auto-sync            # 会话内 checklist 项
    required: [goal-keeper 批准成军即登记注册表，解散即补记]
```

### 6.2 每次成军的验收

DecisionRecord 齐（三问事前+预测+事后校准）；AOOS 完备（政策块/降级拓扑默认节/终审栏）；产出符合所在环境的知识落盘格式；fresh 验证（验证者与产出者无共享上下文）；学习闭环（固化或显式不固化留痕；三字段已记）。

### 6.3 递归的边界（自我变更治理，全部落不可委托内核）

1. **本规范、政策层默认条目、模板层默认条目**的任何修改 = 不可逆决策，唯一路径 goal-keeper 终审；成军官可起草"改进提案"，执行属另一个经批准的组织。
2. 轻量通道准入条件（单 actor / 零外部副作用 / 完全可逆）为规范显式定义，扩条件即修规范，回第 1 条；分类初判在成军官，确认权在 goal-keeper。
3. 成军官无权单方面 active 化缓存条目（固化双门在 C4，裁决在 goal-keeper）。

### 6.4 信任与额度

首次合作：全量验证建立信任（Evidence Before Trust）；建立后：降低验证密度（信任的经济价值）；维持期：显式抽样率校准（防额度透支——AI 输出的高可信表象会让组织误判额度充足）。多子组织并行时监督负载合并记账，超限先降并发、再收窄作业面，**不降验证标准**。

## 第七章 死法预演（七条，概率×代价，词典序）

| # | 死法 | 机理 | 内置对策 |
|---|---|---|---|
| D1 | 缓存僵化 | 新目标被硬套旧模板 | 未命中即生成（C3 恒在场）；条目有效期复验；门可复审 |
| D2 | 自我膨胀 | 一切目标都全量成军，门比活多 | 轻量通道 + 门数预算（带宽不足收窄作业面而非降标准） |
| D3 | 判断带宽破产 | N 个子组织的终审汇聚，人类带宽先死 | 轻量通道免全审 + 额度化 + 例外路由 + 带宽总账超限降并发 |
| D4 | 学习污染 | 错误经验被固化，第二次放大学费 | 固化双门；条目带适用边界与负例 |
| D5 | 同目标双组织 | 并行会话各自成军同目标 | C1 查重闸 + 批准即登记 |
| D6 | 递归失控 | 自我修改/自我授权/目标漂移到"改进自己" | §6.3 三条硬边界 + 维持现状须作为候选比较其死法 |
| D7 | 成军官失效/上下文腐化 | 常设 actor 累积上下文恰是禁止常设审查员的理由；对自己豁免失效预演 | 对己不豁免（本行即预演）；会话自举协议（§5.3）不依赖记忆；goal-keeper 停摆即安全停机；成军官产物（锚点/派发合同）经试点或 fresh 复核 |

## 第八章 度量与诚实边界

**最简三字段**（每次成军必记于注册表行）：成军耗时（起点=目标进入时间戳，C1 落盘强制捕获）、缓存复用构件数、本次新固化数。递减性 = 三字段时间序列，**按通道分层统计**（轻量/全量分开，防通道重分类制造假递减）；意外率（Surprise Rate）沿用 DecisionRecord 校准栏。不做硬编码计数陈述——一律指针式（"以注册表为准"）。

**诚实边界**：判断质量只能防流失不能凭空造；组织证据为自产实证、现场演示级；零数据下的收敛性可重复、尚未证明可收敛——首次运行即是第一批读数。

## 第九章 使用手册（独立运行）

### 9.1 冷启动清单（新环境从零开始）

最少要素，全部就位即可运行：
1. **一个人类**（goal-keeper，愿意在四触点出场）；
2. **一个 AI 会话**（能读写文件、能派发无共享上下文的子代理：researcher / verifier / 敌意审查员）；
3. **四个文件区**：①注册表（一个 md 表格即可：组织名/日期/通道/状态/三字段/意外率）；②缓存库（三层，初始可为空——未命中即生成是常态，缓存随成军累积）；③本规范；④最近 DecisionRecord 未闭合项（初始为空）；
4. 政策继承块直接抄 §6.1。

### 9.2 一个目标的完整走法

1. **目标进入**：人类向会话提出（例："按成军局处理：<目标描述>"）。
2. **C1**：成军官完成三问初答 + 注册表查重 + 通道初判，向人类提交**分类建议及理由**；人类确认分类。
3. **轻量通道**：单 actor 按 checklist 执行 → 登记 → 校准 → 结束（典型耗时：一次会话内）。
4. **全量通道**：
   a. 缓存查询，列出命中构件（哪些模板/政策/角色可直接复用）；
   b. 未命中部分按 §10.1 模板生成 AOOS 草案 + §10.2 DecisionRecord；
   c. 视规模敌意审查（fresh 子代理攻击设计与死法栏）；
   d. **人类批准成军**（批准即登记注册表，记三字段之起点）。
5. **运行**：波次派发防过载；批量任务试点先行；每个 actor 只写自己的文件；降级拓扑已预置；人类只在例外/停机/不可逆点出场。
6. **验收**：fresh verifier（无共享上下文，只读只报告）；其结论为 Pre-Verified，**人类授 Verified**。
7. **学习**：事后校准回填（§10.2 表）；固化判定（双门 + 人类裁决）；三字段记账。
8. **解散**：终审栏留档，注册表补记，子组织关闭。

### 9.3 人类使用指南（一页）

- 你做的事：四触点（§5.4）+ 一条红线。
- **红线**：不要替 AI 做它的判断（它会自己走门控），也不要让 AI 替你做你的终审（它的"已完成"只是 Pre-Verified）。
- 你会收到的请求只有四类：确认通道分类 / 批准成军 / 处理例外 / 终审。其余时间不被打扰即为系统健康。
- 如果长期不在线：系统停在待批行，安全停机，不会自行越权。

### 10.2 DecisionRecord 模板

```markdown
**决策：<一句话>**
```

### 10.3 角色构件库（九角色 × 四要素）

| 角色 | responsibility | authority | constraints |
|---|---|---|---|
| goal-keeper（人类） | 持目标意图；对 Type III Error 负最终责 | 接受/否决一切；不可委托内核 | 四触点出场；不代行 AI 判断 |
| coordinator（成军官/协调者） | 组织形成、分解委派、单写者落盘、综合、不代替下级下结论 | 写注册表/缓存/AOOS；派发子代理（判定者派发须人确认） | 禁不可逆操作；无 active 化裁决权；产物经试点或 fresh 复核 |
| researcher ×N | 单线"溯源→精读→落盘"，每条结论带锚点 | 只读外部 + 只写自己文件 | 禁凭记忆引用；截断显式标注 |
| verifier | 合规审计 + 数字抽查，自写脚本实测 | 只读 | 只报告不修复；与产出者无共享上下文 |
| hostile-reviewer | 以推翻草稿为任务攻击（证据/去重/可执行性/死法遗漏） | 只读 | 只报告；判决三选一（ACCEPT/notes/REWORK） |
| index-writer ×N | 只写分到的目录的索引/日志 | 最小权限 | 不改研究内容 |
| scout（侦察前置） | 定材料可得性天花板，据此改写目标尺度 | 只做事实侦察 | 不下内容结论 |
| curator（缓存吏，可由协调者兼任） | 缓存登记、复现计数、有效期复验 | 起草与计数 | active 化须人裁决 |
| fetcher（获取员，常被 researcher 自带能力吸收） | 外部内容获取降级链执行 | 按降级链 | 不改写内容 |

## 附录 A 敌意审查摘要（18 处击穿一览）

无共享上下文审查员四面攻击（理论失真/递归失控/可行性/死法遗漏），判决 REWORK。关键击穿与处置：
1. **P0** 轻量通道无人类触点（判定者自免审）→ 加分类确认触点与政策 classification-confirmed；
2. 登记时机矛盾（政策"批准即登记"与流程图"验证后登记"冲突）→ 统一为批准即登记；
3. 固化双门无分权（派发/判定/写入集于协调者一身）→ active 化与 fresh 派发确认收归人类；
4. 政策层可绕过变更门（改缓存政策=实质自改规范）→ 变更门显式扩至政策层与模板层；
5. 无守护进程下"自动"条款无执行主体 → 全部改称会话内 checklist 强制项 + 自举协议；
6. 对己豁免失效预演 → 补第七死法 D7；
7. 引用失真 3 处（晋级阶梯实为放宽、常设先例仅两例、原文题名）→ 如实改写；
8. Goodhart（通道重分类制造假递减）→ 分层统计；可逆性过强（忽略已扩散引用）→ 改"本体可逆，引用逐一回收"；理论版本无钉扎 → frontmatter 钉扎。
方法论记录：P0 击穿证明"审查强度不对称是设计者的固定盲区"（全量通道记得设人审，轻量通道忘了）。

## 附录 B 术语速查

**成军**：按规范实例化一个临时组织。**goal-keeper**：持不可委托内核的人类席位。**成军官（formation-coordinator）**：常设 AI 协调者。**轻量通道**：免全量成军的单 actor 路径。**固化双门**：缓存条目转正的两条路径（第二次独立复现 / fresh 审查）。**Pre-Verified / Verified**：AI 验证结论 / 人类授予的最终验收。**fresh**：无共享上下文新开实例。**安全停机**：停于待批而非伪造继续。
