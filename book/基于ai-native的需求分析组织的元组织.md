## 出版说明

本规范是通用元组织（formation-bureau）在**软件研发需求确认场景**的特化：其上游为《AI 原生组织理论》（§39 需求分解保真、§40 可能性空间收敛、总纲出口规则、操作手册六步路径与双保障）。特化原则：通用机制（目标闸/缓存/门控/治理/学习）不变，生成器内容替换为需求域构件（五层漏斗/五道裂缝/三件套/假设台账/存量测绘）。

**诚实边界**：①本规范是实例化不是验证——需求场景尚无一次完整运行证据，首次运行即第一批读数；②理论自认"多跳委派无模型"，平台方-开发商-客户三明治结构暂不覆盖；③判断质量只能防流失不能凭空造。理论再版后须复核本文件。

## 第一章 定位：需求局是什么

### 1.1 核心重述

**需求确认不是信息收集活动，是可能性空间的收敛过程。** 一句话需求的缺陷不是缺信息，是**缺尚未做出的决策**——追问细节的收敛效率接近零（开放性问题信息量≈0），正确做法是枚举决策维度、逐个二叉切割。**商业目标的角色 = 价值函数（选择压力）**：AI 强于扩张（枚举维度、生成候选）、弱于收缩（判断哪个对）——收缩需要价值函数，而价值函数只能由承担后果者提供。**存量系统 = 组织缓存的物理形态**（成功协作的固化 + 认知债）。

### 1.2 元策略

最优需求路径不存在，存在的是最优元策略：**生成（枚举维度、生成候选）+ 门控（词典序判定，先挡死再优化）+ 收敛（每次决策砍掉一半空间，反馈缩小下一轮）**。需求不是被"调研"出来的，是被生成和筛选出来的。

### 1.3 常设与临时

永久存在的只有：治理席位（价值函数持有者）、需求缓存（判据库/维度库/异常库/依赖地图）、门禁、学习引擎——**没有执行层**。每次需求分析按目标成军一个临时需求分析组织，锁定即解散；判定类角色（verifier/敌意审查员）每次新开无共享上下文实例。

### 1.4 不是什么

不是需求文档工厂（产出是**被锁定的决策集**，文档只是载体）；不是把需求交给 AI 全自动收敛（L1 不可逆维度与 L3 偏好选择永远在人）；不是漏斗层数越多越好（轻量通道存在，且大多数日常需求该走它）；**不是在找"最优解/最大价值解"**——最优不可判定（元回答：最优路径不存在，存在的是最优元策略），锁定的是停止规则触发时**足够好且可退**的解，价值函数本身在探索中显影演化而非预先给定。

## 第三章 Goal 治理（需求局自身的 Locked Goal）

**Goal：对经委托进入的任意原始需求（可为一句话），可靠地产出一个经收敛与门控的 Locked 需求包（三件套齐 + 五道裂缝闭合 + 假设台账挂接 + 存量依赖/禁区声明），并使同类需求的收敛成本递减。**

**AC（缺一不算完成）**：①成军前查重（无在航同目标需求组织）；②DecisionRecord 三问落盘；③Locked 需求包落盘且**全部 AC 为描述性语言**（无"体验更好"类评价词残留）；④五道裂缝问卷逐条有答案或显式"留白待决+归因"；⑤假设台账挂接（每条需求标注验证哪个商业假设）。
**负例**：产出仅会议纪要/对话结论；AC 含评价性语言；负例栏空缺；未过人审即进入开发。
**优先级**：判据正确性 > 判断带宽节约 > 收敛速度。

## 第四章 六大组件

### C1 需求闸（成军前台）
原始需求进入 → 三问过目标（含 Type III 与 Status-Quo：不做也是候选）→ **通道初判**（表 §5.2）→ 分类结论经 goal-keeper 确认。硬约束：落盘记录**进入时间戳**；存在性断言（"系统已有 X 功能"）必须标注读取时点。
*消解*：Type III（做不该做的）；需求组织自我膨胀。

### C2 需求缓存（四库一图）
- **判据库**：已验证的商业/技术判据措辞（评价性→描述性转译的先例）；
- **维度库**：按需求类型的决策维度清单（L0 的种子——同类产品的已知决策空间）+ **隐含指标模板**（v0.5：按需求类型的 NFR 结构种子——性能/可用性/安全/兼容/合规，供同型对照勾选提问，数值禁抄须本地来源）；
- **异常库**：历史异常路径与禁区条款（需求质量≈异常完备度）；
- **假设台账库**：商业假设→判据→证据的回填记录；
- **依赖地图**：存量系统的模块-依赖-风险标注（升级时的缓存 schema）。
读写协议：单写、子组织只读；固化双门（第二次独立复现或 fresh 审查）+ 同域冲突检查 + 每条带复验条件。

**行业先验供给（v0.4，四层分级制）**：外部规范按**先验强度递减、失效速度递增**分四层，叠加用途映射——**硬约束**（法规、安全与强制标准）→ 直接进五道裂缝"禁区"栏（切子空间，不参与权衡）；**半强制**（行业标准与协议规范）→ 可协商但违反代价=生态不兼容，默认遵守、偏离须留档；**参考性**（最佳实践/参考架构）→ 维度库与判据库的种子（每条标 [来源/环境前提/适用判断]；违反走显式 ADR 记录）；**启发式**（SOTA/竞品）→ 差异化矩阵（"哪些维度故意不同+为什么"，非抄单——竞品的解是在竞品商业假设下验证的）。核心框架：借鉴的约束 = **带先验的假设**（未在你处验证），经**本地验证后升格为契约正式条款**（先验升格阶梯，与缓存 candidate→active 同构）；先验的最强形态是**代码先验**（可运行的行业基线系统——约束以代码存在，天然可执行且已验证）。借鉴完成后必产**剩余特异不确定性清单**（行业清零通用不确定性，特异部分是探针/灰度预算的唯一去向）。防三死法：行业均值当自己最优（代拟行业版）；行业共识+AI 双源同错（预训练≈行业实践内化，误差相关→回声室，须至少一方接触自己的 L4）；**过度约束→可行域为空**（约束互斥时被迫违反的常是最不该违反的那条）。
*消解*：同类需求第二次从零收敛；存量升级依赖暗雷。

### C3 收敛引擎（五层漏斗为标准管线）
**C3a 维度枚举器**（L0）：fresh 子代理并行展开决策维度（平台/数据 schema/兼容矩阵/计费/合规/性能/迁移/团队能力…），人补充；**C3b 候选生成器**（L2）：对剩余可逆维度生成 ≤3 个差异最大化候选，人只看差异矩阵；**C3c 原型器**（L3）：低成本原型并排呈现——**构造偏好而非回忆偏好**；**C3d 存量测绘/探测器**（双模式，详见 §5.6）：可测绘时——依赖分析 + 禁区问卷 + 缓存 schema 重建；**不可全知时（默认存量/开源场景）——降格为行为假设化地图**（节点标 [已知/推断/未知]）+ 探针队列（特征测试/影子流量/回放/并行跑），读码推演只生成假设不构成决策依据。

### C4 门禁（词典序，先挡死再优化）
①**三件套门**：AC 可判定 + 负例非空 + 优先级排序存在；②**裂缝门**：五道问卷逐条闭合；③**代拟门**（I-DISC）：商业判据不得由生成方自判——判据终审在 goal-keeper；④**敌意审查门**（中大型需求必设）：fresh 审查员攻击 AC 可判定性/负例覆盖/异常完备度/假设台账真实性；⑤**原型门**：涉及用户偏好且成本可承担的需求，未过 L3 不得锁定；⑥**编排者失效预演**：DecisionRecord 死法栏必含协调官自身失效项；⑦**不变量与假定分流门**（v0.5）：探索出的约束三分流——硬约束走不变量五级阶梯（自然语言禁区→声明式 □谓词→时态安全属性→可执行【断言/契约/属性测试】→类型级，尽量右移），可协商项写**显式假定**（`假定+依据+违反预案`——把验收分歧前移到锁定期），启发式逐出清单转默认值；隐含指标按八法挖掘（边界值/反事实损坏/依赖追问/同型对照/主体细分/时间箭头/探针实测/合同考古），优先挖"外部可见×不可逆"的功能。

### C5 治理层
不可委托内核（goal-keeper）：**L1 不可逆维度决策、L3 原型偏好选择、判据终审、锁定批准、灰度结果认可（Verified）、本规范变更**；验证额度（信任三段制）；判断带宽总账（多需求并行时监督负载合并记账，超限先降并发）。

### C6 学习引擎
假设台账回填（上线数据→假设验证结论，第二次不交学费）→ 四库固化 → 收敛成本三字段记账（收敛耗时/缓存复用构件数/本次新固化数，按通道分层）→ 注册表同步（批准即登记、解散即补记）。

## 第五章 运行时

### 5.1 双层循环

```
原始需求进入（goal-keeper 委托；C1 记时间戳）
 → C1 需求闸：三问过目标 / 查重 / 通道初判（人确认分类）
 ├─ 轻量通道：单 actor + 裂缝问卷 checklist + mini 三件套 + 登记 + 校准 → 结束
 └─ 全量通道：
    [存量场景先走] C3d 测绘：依赖分析 + 禁区问卷 + 缓存 schema
    → C2 缓存查询（维度库命中→L0 短路）→ C3 漏斗 L0→L1→L2→L3
    → C4 门禁（三件套/裂缝/代拟/敌意审查）
    → goal-keeper 锁定批准（批准即登记注册表）
    → 移交开发组织（本规范边界止于此；灰度证据回填接口见 C6）
    → 假设台账回填 + 固化 + 记账 → 需求组织解散 → 缓存增值 → ↺
```

### 5.2 路由决策表 v0.1（candidate，首次实测后重估）

| 需求类型 | 通道/组织形态 | 关键门 |
|---|---|---|
| 单点小需求（可逆、无商业判据争议） | 轻量：单 actor + 裂缝 checklist + mini 三件套 | 人确认分类 |
| 新产品/新模块需求 | 全量漏斗：L0 并行枚举 ×N + L1 人主导 + L2 生成 + L3 原型 + 敌意审查 | 原型门 + 三件套门 |
| 存量平台升级需求 | 测绘/探测双模式（§5.6）→ 契约界面先行 → 增量漏斗 | 探针优先于完整测绘 + 禁区问卷 + 契约测试 + 试点灰度设计 |
| 商业模式验证型需求 | 假设台账驱动，L4 权重最大（最小可验切片优先） | 假设台账挂接 + 灰度证据才算数 |
| 涉及不可逆承诺（定价/对外 API/数据模型） | L1 逐项人决策 + 出口规则切小 | 代拟门 + goal-keeper 逐项签字 |

### 5.3 会话自举协议（无守护进程，一切"自动"=会话内 checklist 项）

协调官每次会话按固定清单恢复状态：①注册表（在航/待批）；②四库一图（缓存状态）；③本规范；④最近未闭合的假设台账项。goal-keeper 不在线 = 停于待批，安全停机，无超时自动越权。

### 5.4 人类触点（全部出场时刻，共五个）

| 触点 | 做什么 | 为什么不可委托 |
|---|---|---|
| 需求受理与通道确认 | 确认分类（轻量/全量） | 防判定者自免审 |
| **L1 不可逆维度决策** | 对外 API/数据 schema/定价/品牌承诺逐项拍板 | 价值函数只能由承担后果者提供 |
| L3 原型偏好选择 | 在并排原型中选（或都不选） | 偏好无法被代答，构造≠回忆 |
| 锁定批准 | 过目 Locked 需求包与 DecisionRecord | 三件套是开发的输入，错则全链错 |
| 灰度结果认可 | 授 Verified（接受/否决/迭代） | AI 与数据只构成 Pre-Verified |

### 5.5 震荡管理与基准切换协议（v0.2 收编）

**核心定义**：震荡 = 单位成本信息增益 ≤ 0 的循环——减少震荡与加速收敛是同一件事。

**分型速查**：可逆维度上带数据锚点的震荡 = 健康迭代（保留）；三种病理震荡（杀死）：**不可逆维度反复**（升级人 + 出口规则切小）、**无新证据摇摆**（≥2 轮无新锚点即"平了就停"）、**违反 T_m 的重组**（变更门拦截）。第四种隐患是**锚定震荡**（对话历史把早期输出固化成"事实"）——会话分离是解药。

**根锚规则**：基准的根锚是**商业目标**，不是需求也不是实现。需求 = 商业目标的想象侧表示（可动），实现 = 判定侧表示（可动）。**实现只是可观测性更高；置信度来自验证状态**——已验证行为数据（证据）的置信度高于未验证想象，但未验证行为的可观测性 ≠ 置信度：把未验证实现扶正为基准触发 **Hyrum 效应**（一切可观测行为含 bug 被下游依赖 → 隐性需求固化、"无人认领的事实标准"）。故证据只能**回写需求内容**、不能**篡夺基准位置**（实现自任基准 = "能做什么就做什么" = Type III 后门）；且"行为已被验证 → 回写需求"**不可省略**——它是防止 Hyrum 固化的唯一手段。基准持有者永远是从后果中受益/受损的人。

**切换触发器**：

| 触发 | 判据 | 动作 |
|---|---|---|
| T1 不可达 | 能力/物理/成本实测失败 | 证据回写需求 → 反向校准 → 人重决策 → **再锁定** |
| T2 证伪 | L4 数据与 AC 冲突 | AC 修订走变更门（证据优先，人签） |
| T3 空转 | 同一冲突 ≥2 轮无新锚点 | **分解优先**：拆"已验证子集（锁死进契约）+争议子集（单独 spike/降级）"——反复震荡常意味着需求不可行/不自洽或验收测错对象；分解后仍空转才升级人裁决（不是切换基准）；不可逆维度用出口规则切小 |

**铁律**：任何切换必须以**再锁定**结束（新 Locked 需求包 + 变更门留档）——双向同时在动 = 基准真空，系统最差状态。

### 5.6 存量与开源基座协议（v0.3 收编）

适用：现存系统 / 开源系统基座，**系统现状不可完整理清**（黑盒或半黑盒）且商业需求在变动——双不确定同时成立。核心反转：**不再投资于看清任何一侧，把工程投资集中在两个不确定性之间的界面上**（合同测试 + 防腐层），让界面成为减震器。

五机制速查：
1. **测绘改探测**：行为假设化地图（[已知/推断/未知]）+ 探针队列（特征测试/影子流量/回放/并行跑）。纪律：读码推演=仿真，不构成锁定依据；探针=便宜且真（信息价目表本地版：推演【便宜可假】< 探针【便宜且真】< 契约【一次投入】< 灰度【贵且真】）；
2. **合同界面工程化**：动哪个区域先立契约测试（把黑盒变可判定组件）；自定义逻辑全放防腐层 ACL（存量怪异模型不入自有代码）；替换走绞杀者（新旧并存、按路由渐进、并行跑持续对照）；
3. **Feature flag 矩阵 = 可能性空间的运行时参数化**：可逆维度编译成开关而非硬编码——商业变动从"重新开发"降级为"翻开关"（震荡搬进可逆区的终极工具）；开关带 TTL 与清理责任（防 flag 债务）；
4. **分层短锁定 + 三线并行**：不可逆维度短租约+变更门；可逆维度显式留白或 flag 化；探针/界面/最小切片并行推进（试点与锁定并行）；最小切片选"商业假设最强依赖 × 探针热点最集中"交集；
5. **开源上游漂移 = 环境漂移的代码化身**：自有定制收进扩展点/插件/ACL，fork diff 压最小，上游合并走定期窗口，合并前跑契约测试。

场景死法：完整理清的执念（B1）/ 需求追认全盘重做（B2）/ 探针污染生产（B3，探针自身须可逆）/ 合同漂移黑塔回流（B4，契约测试入硬门）/ 上游漂移击穿定制层（B5）。

### 6.1 政策继承块（所有子组织自动继承）

**基础纪律**：三问决策前置；一切产出落盘（不落盘不算完成）；先想清楚再动手；只改该改的；禁止不可逆破坏性操作；判据先行于方案。

## 第八章 度量与诚实边界

**收敛四字段**（每次记录于注册表行，按通道分层）：收敛耗时（进入时间戳→锁定批准）、L0 显式化维度数（其中缓存命中数）、锁定时仍未决（显式留白）维度数、假设台账回填率。递减性=字段时间序列；不做硬编码计数陈述。

**震荡三判据**（健康度监测，v0.2 收编）：①不可逆维度集合单调缩小（回弹=病理）；②震荡幅度 / Surprise Rate 衰减（不衰减=未在学习）；③每次重开都有台账数据锚点（无锚点=空转，触发"平了就停"）。**每轮对抗三记账**：成本、淘汰候选数、新增锚点数——期望信息增益的序数代理（基数化挂账 G-S6）。

**诚实边界**：实例化非验证（无一次完整运行证据）；多跳委派（平台-开发商-客户三明治）不覆盖；判据量化转译规程未模板化（挂账）；判断质量只能防流失不能凭空造。

## 第九章 使用手册（独立运行）

### 9.1 冷启动清单
①一个人类（愿意在五触点出场，尤其 L1）；②一个 AI 会话（能读写文件、能派 fresh 子代理）；③四个文件区：注册表（md 表格）、四库一图（初始可空——未命中即生成是常态）、本规范、未闭合假设台账（初始空）；④政策块直接抄 §6.1。

### 9.2 一个需求的完整走法
1. **进入**："按需求局处理：<一句话需求>"。
2. **C1**：协调官完成三问初答 + 查重 + 通道初判 → 向人类提交分类建议与理由 → 人类确认。
3. **轻量**：单 actor 过裂缝问卷 checklist → mini 三件套（AC≤3、负例≥1、优先级排序）→ 人批准 → 登记 → 结束。
4. **全量**：
   a. 存量场景：测绘员出依赖地图 + 禁区清单（人类确认禁区红线）；
   b. L0：≥2 个 fresh 枚举员并行展开维度 → 合并去重 → 人补充 → 维度清单落盘；
   c. L1：协调官标出不可逆维度子集 → **人类逐项决策**（可要求 AI 只做后果推演，不做推荐排序之外的判断）；
   d. L2：生成器出 ≤3 差异候选 + 差异矩阵 → 人审阅；
   e. L3：原型器并排呈现 → 人选择或打回；
   f. C4 门禁：三件套/裂缝/代拟检查 + 敌意审查（中大型）；
   g. **锁定批准**：人类过目 Locked 需求包 → 批准即登记 → 移交开发。
5. **回填**：上线后灰度数据 → 假设台账回填 → 固化判定（双门）→ 四字段记账 → 解散。

### 9.3 人类指南（一页）

细节超载时的带宽纪律（v0.5）：**你的带宽只花在基准上**（AC/不变量/不可逆维度/L1/终审），细节全部交给机器可判的载体（一条判据压无限验证、一条不变量压整类状态、一张差异矩阵压全部方案）；上浮给你的一定是选择题（带后果推演与可逆性标注），不是论述题；超预算即 Safe Halt——停，不降标准；红线：委托执行，不委托判断力维持（不可逆亲自推演、关键抽样保留人亲自份额）。
- 你的五触点见 §5.4；**红线**：不要替 AI 枚举维度（它比你见得多），也不要让 AI 替你做 L1/L3/终审（它没有后果）。
- 你会收到的请求只有五类；其余时间不被打扰即系统健康。
- 说不出要什么时不要硬答——要求进入 L3（选得出比说得出可靠）。

## 附录 A 敌意审查继承与本域新增风险

继承成军局 v0.1 的 18 处击穿修复（要点：判定者不得自免审、登记时机=批准即登记、固化分权、政策层纳入变更门、自动化=会话内 checklist、对己不豁免失效预演）。本域新增已识别风险：①L3 原型的"偏好引导"污染（原型器预设推荐）→ 已入 constraints；②假设台账的"事后合理化"（上线后牵强归因）→ 回填须附数据锚点；③五触点的人类负担（比通用成军局多一个）→ L1 可授权"预决策清单"由人批量裁决，但不可整体委托；④对抗无棘轮则发散（GAN 式不稳定）→ info-gain-ledger 强制记账 + 零增益停止审查（v0.2 增）；⑤**R-Hyrum：行为已被验证而未回写需求 → 隐性需求固化**（比基准真空更隐蔽——系统看起来正常运转，实现的偶然行为被下游依赖成"事实标准"）→ 回写纪律不可省（v0.4 增）。

## 附录 B 术语速查

**Locked 需求包**：三件套+裂缝+维度清单+存量声明的完整决策集。**不可逆维度**：错了无法或极难回退的决策（对外 API/数据 schema/定价/品牌承诺）。**留白**：显式声明未决且归因的维度（不是遗漏）。**四库一图**：判据/维度/异常/假设库+依赖地图。**ground truth**：只有 L4 真实用户证据。
