# 基于 AI-native 的工程基础设施部署规范

## ——独立可执行规范 v0.1

## 出版说明

本规范是 AI 原生组织理论五局元组织规范（成军局/需求局/开发局/测试质检局/生产局）的**工程基础设施层**：把五局持有的**治理性基础设施要求**（会话自举/降级拓扑/单写者/上游漂移/外部锚/产物落盘/带宽总账）落成**工程性/部署性规格**（worktree/token/监控/预算/并行度/模型选型/存储/版本控制/网络/部署形态），保障理论落地到具体工程环境。

**分层关系**：五局规范是组织规范（治理层，持不可委托内核/价值函数人属/判断带宽/Pre-Verified≠Verified）；本规范是部署规范（工程层，持工程规格）；两层互补，治理性要求不下沉到本层。

**适用**：任何"人类 + 可派子代理的 AI 会话"组合，在具体工程环境（单机/分布式/云）运行 AI-native 组织时，用本规范确定工程基础设施。

**实证依据**：Nous Research Hermes 自重构案例（1393 子智能体/19 小时/代码库 -34.4%）暴露的工程缺口（git worktree 无规范/token 过期杀整轮/218 并发无上限/65 处异常靠社区评审/$19300 无预算红线）。

## 第一章 定位：部署规范 vs 组织规范

部署规范不替代组织规范。本规范只定"用什么工程基础设施 + 怎么部署"，**不持有**判断权归属/不可逆决策红线/验收最终授予（这些在五局 goal-keeper 不可委托内核）。

部署规范的原则：
1. **工程规格服务治理要求**：每项工程规格落地一条治理要求（如 worktree 落地单写者 R8/R9）。
2. **不硬编码计数**：指针式（以试点注册表为准），所有数字（并发/预算/上限/TTL）待 Phase 1 校准。
3. **可逆参数化**：规格带 TTL，可调可回退（flag-with-ttl 同型）。
4. **实例化非验证**：v0.1 草案，须 Phase 1 试点复现≥2 + fresh 审查才 active。

## 第二章 治理锚点总览（五局已有，本规范落地）

本规范落地的治理要求（详细条款见五局规范，本规范引用其结论）：
- 单写者 R8/R9 + 会话分离（需求局）

## 第三章 10 项工程规格条款（可执行级，带 TTL）

### 01 工作空间隔离（P0）

**治理锚点**：R8/R9 单写者+会话分离 + probe-over-mapping + §162 不可逆写入

**工程规格条款**：
1. 每子组织/子代理一个 git worktree，路径 `<repo>/.worktrees/<org-id>/<task-id>` 互不重叠。
2. 单写者：每产物单一写入者，其他 worktree 只读；并发走互不重叠分组（R16 决策闭包）。
3. 隔离边界=文件路径不重叠。
4. 冲突检测=合并前契约测试（upstream-drift-guard）。
5. fresh 审查员独立 worktree（R8 I-DISC，无共享上下文）。
6. worktree 带 TTL：任务完成/超时即 `git worktree remove`，防 worktree 债务。

**probe**：2 子代理独立 worktree 改不重叠文件+1 fresh 审查 → 测不覆盖+契约门+fresh 可行。
**待 Phase 1**：派发深度/并发数/TTL（指针式）。

### 02 token 与凭据管理（P0）

**治理锚点**：会话自举 §5.6 + 安全停机 §397 + 协调官失效预演 + I-21 外部锚

**工程规格条款**：
1. token 过期前探针主动续期（不靠人发现）。
2. 续期失败→安全停机（停于待批不伪造继续）。
3. 凭据不入产物文件，进独立 secrets 后端，AOOS 用指针引用。
4. 凭据三件套：身份/授权/审计。
5. 断点恢复：复用 §5.6 会话自举 checklist（注册表/缓存/规范/未闭合台账）+ checkpoint（worker 提交+brief+DecisionRecord 落盘）。
6. DecisionRecord 死法栏必含"token 过期杀整轮"项+恢复路径。

**probe**：30 分钟任务 token TTL=10 分钟强制过期 3 次 → 测续期+安全停机+断点恢复+失效预演。
**待 Phase 1**：续期阈值/checkpoint 频率/凭据后端选型（指针式）。

### 03 故障监控栈（P1）

**治理锚点**：协调官失效预演 + 安全停机 §397 + 告警麻木先兆 §275 + 告警风暴防护 §418⑧ + Chaos Drill §2213 + L3 验证 §3188 + 决策界面结构化 §120

**工程规格条款**：
1. 监控 5 失效面：进程存活/token 剩余/触点时延/落盘完整性/契约性质违反。
2. 自动检测（定时探针，不靠人）。
3. 告警上浮必是选择题带后果+可逆性（§120），不裸告警。
4. 告警风暴防护：分级（致命/警告/信息）+批量窗口+告警麻木先兆监控（Override 趋零即病态）。
5. 致命失效→安全停机（§397）。
6. 关键不变量编译为 L3 监控器（§3188，如"单写者不并发写"→文件锁监控）。
7. 周期性 Chaos Drill 注入故障测兜底（§2213）。

**probe**：3 子代理注入 3 故障（进程崩+token+风暴）→ 测检测+选择题+风暴压住+麻木先兆。
**待 Phase 1**：心跳频率/分级阈值/L3 范围/演练周期（指针式）。

### 04 成本预算红线（P1）

**治理锚点**：判断带宽总账 C5 §120 + 信任三段制 + 四字段 §251 + 超限 Safe Halt + R25 信息增益停止 + D3 带宽破产

**工程规格条款**：
1. 预算三段制：主跑（全量硬上限）/修复（信任后降密度）/监督（抽样率显式）。
2. 成本递减四字段记账：耗时/复用构件数/新固化数/Surprise，按通道分层防 Goodhart；指针式。
3. 超限→Safe Halt（停于待批不偷跑降标准）；上浮选择题（加预算/降并发/停/偷跑风险）。
4. 零增益轮触发停止（R25，不 churn）。
5. 人工评审/社区评审时间进成本账（不只记模型费）。

**probe**：3 子代理跑到预算上限 → 测 Safe Halt+选择题+四字段+零增益停+人工计价。
**待 Phase 1**：主跑预算/修复比例/Safe Halt 阈值/人工判价（指针式）。

### 05 并行度上限（P1）

**治理锚点**：带宽总账超限降并发 C5 §120 + D3 带宽破产 + T15 判断带宽不等式 + 三前提（R16+R8/R9+R5）

**工程规格条款**：
1. 并发三前提门：① 分组互不重叠（R16）② 独立检出（R8/R9，见 01）③ 量化验收（R5）——全过才并发，缺任一→串行。
2. 并发硬上限（指针式，按通道分层防 Goodhart），超限降并发不偷跑。
3. 终审不一次性汇聚，按里程碑批量+冻结窗口（节奏解耦防 D3）。
4. 降并发仍超限→Safe Halt；上浮选择题。
5. 与 04 联动：并发↑→预算↑，Safe Halt 同步降并发。
6. 告警麻木先兆：并发超限时触点时延拉长+Override 趋零（接 03）。

**probe**：10 子代理并发上限=3+15 分组 → 测三前提门+降并发+批量终审+Safe Halt+麻木先兆。
**待 Phase 1**：并发上限/深度/批量窗口/降并发阈值（指针式）。

### 06 模型选型准则（P2）

**治理锚点**：T4 Capability Before Identity + R8 I-DISC + R8/R9 fresh 上下文 + T15 判断带宽 + I-21 外部锚 + 成本递减

**工程规格条款**：
1. 按角色能力选型（T4）：生成角色选扩张强/判别角色选收缩强且与生成分离/协调角色选长上下文。
2. I-DISC 硬约束：生成与判别模型/会话可分离，不可分离→否决。
3. fresh 上下文要求：模型支持开无共享上下文新会话。
4. 能力够用即停（不追最强，追过 AC 可判定线 R5）；指针式。
5. 验证需求不超 goal-keeper 带宽（T15），超限→降并发（05）或换模型。
6. 推理调用留可追溯记录（I-21），A2 可核。

**probe**：生成+判别两角色选不同模型 → 测 I-DISC 分离+fresh+带宽不超+可追溯+成本在控。
**待 Phase 1**：模型清单/能力阈值/带宽估算/切换 TTL（指针式，依赖真实环境）。

### 07 产物存储后端（P2）

**治理锚点**：产物落盘 §187 + 指针式 §251 + 双账本制 §108-115 + 缓存条目 schema §351 + R8 单写者 + probe-over-mapping

**工程规格条款**：
1. 双账本分层存储：蒸馏层（patterns/协议/AOOS，可独立交付 P-015）+ 回放层（运行记录/DecisionRecord）+ 注册表（度量指针）。
2. 缓存条目 9 字段 schema 落盘（id/layer/content/source_event/applicability/negative_example/status/reproduction_count/recheck_condition/read_at）。
3. 单写者：协调官写，子组织只读；并发走 01 worktree+固化双门。
4. 存量探针查询（不全量读码，probe-over-mapping）。
5. 固化双门：candidate→active，裁决在 goal-keeper。
6. 后端按规模：小规模文件系统+git / 中规模+对象存储 / 大规模+DB 索引。

**probe**：产 1 缓存条目+1 DR+1 注册表行 → 测三分层+schema 完整+单写者+探针可查+双门。
**待 Phase 1**：后端选型/检索方式/保留期/格式（指针式，按规模）。

### 08 版本控制策略（P2）

**治理锚点**：upstream-drift-guard + contract-as-interface + probe-reversible + flag-with-ttl + §162 不可逆写入 + R8 单写者 + §187 产物落盘 + R12/R13 Pre-Verified≠Verified

**工程规格条款**：
1. 分支模型：main（保护）+ `<org>/<task>`（子组织分支，见 01 worktree）+ `integration/<milestone>`（里程碑批量）；禁直推 main。
2. 契约测试门：合并前必跑契约测试（黑盒变可判定）；自定义放 ACL 防腐层；替换走绞杀者。
3. 合并窗口：定期不实时（节奏解耦防 churn）；fork diff 压最小。
4. 断点恢复：每分支提交+brief+DecisionRecord 落盘；复用 §5.6 checklist 续跑。
5. 不可逆写入门：移动/删除/改既有→单写者+依赖分析前置+verifier 自写脚本。
6. Pre-Verified→Verified：合并=Pre-Verified（AI+契约测试），Verified 由人/社区评审授。
7. 可逆改动编译为 flag（带 TTL+清理责任），不直改代码。

**probe**：2 子组织分支改不重叠→契约门→集成→人评审 → 测分支不直推+契约门+绞杀者+窗口+断点+Pre→Verified。
**待 Phase 1**：窗口周期/契约覆盖/对照期/评审轮数（指针式）。

### 09 网络与推理 API 可达性（P2）

**治理锚点**：外部锚 I-21 + A2 外部真值核实员 + 安全停机 §397 + 决策界面结构化 §120 + probe-reversible + Chaos Drill §2213 + D15 缓存命中短路

**工程规格条款**：
1. 可达性探针：定时探推理 API（只读不污染），超时/不可达告警（接 03）。
2. 超时重试：指数退避带上限（防 churn）；上限到→安全停机（§397）；上浮选择题。
3. 外部锚记录：每次调用留可追溯（调用者/时间/模型/输入摘要/返回/状态），A2 可核。
4. 外部锚缓存：高频结果缓存（带 TTL+recheck_condition，复用 §351 schema），命中短路（D15）。
5. 降级路径：网络不可达→用缓存锚/降并发串行（05）/安全停机（§201 同型）。
6. 周期 Chaos Drill 注入网络抖动测兜底（§2213）。

**probe**：调推理 API 注入 3 网络故障 → 测探针+退避+安全停机+选择题+可追溯+缓存短路+演练。
**待 Phase 1**：探针频率/重试上限/缓存 TTL/演练周期（指针式）。

### 10 部署形态（P2，收口）

**治理锚点**：§221 符合所在环境 + §201 降级拓扑 + §5.6 会话自举 + 指针式 §251 + D3 带宽破产 + probe-over-mapping + flag-with-ttl + 成本递减

**工程规格条款**：
1. 形态选型矩阵：单机（单进程+多 worktree，i7+64GB 级）/分布式（多进程+跨机协调）/云（容器编排+弹性）。
2. 从单机起步（probe-over-mapping，不要求先理清全貌），Phase 1 跑通再按需升级（成本递减）。
3. 每形态预置三类降级：限流（05）/过滤（03）/超界（04）。
4. 无守护进程（§5.6），靠 checklist 恢复，goal-keeper 不在线=安全停机。
5. 资源配额（CPU/内存/进程/并发）全指针式，超限触发 05/04。
6. 形态升级触发：D3/04/05 超限→评估升级；升级是可逆决策（flag-with-ttl 可回退）。
7. 符合所在环境（§221）：产物落盘格式随形态（本地文件/共享存储/云存储）。

**probe**：单机跑通 01-09 全 spec 最小任务 → 测全 spec 跑通+降级预置+会话自举+配额指针式+升级触发。
**待 Phase 1**：升级阈值/资源配额/后端选型/回退条件（指针式）。

## 第四章 耦合关系

10 项互相耦合，构成完整工程基础设施层：

- 01 worktree 是 07 存储/08 版本控制/10 部署的载体（独立检出）
- 02 token 是 03 监控/09 网络的检测对象
- 03 监控是 02/04/05/09 的告警通道（决策界面结构化 §120）
- 04 预算 ↔ 05 并发联动（并发↑→预算↑，Safe Halt 同步降并发）
- 06 模型选型影响 04 成本/05 并发/09 推理 API
- 07 存储 = 08 版本控制载体（文件系统+git）
- 10 部署形态汇总 01-09 后端（收口）

## 第五章 Phase 1 试点计划

按 P0→P1→P2 顺序试点，每项 probe + 待校准项见第三章各节。固化条件统一：
- 试点复现≥2 → candidate
- fresh 审查通过（R8 I-DISC）→ active
- active 化裁决在 goal-keeper
- 固化入对应局 C2 构件层 + 6.1 政策

## 第六章 方法自洽

本规范用 AI 原生组织理论自己的方法起草：
- L0 枚举 10 项决策维度（不凭直觉）
- probe-over-mapping（不要求先理清全貌，每项给最小可逆试点）
- flag-with-ttl（规格可逆参数化，带 TTL 可调）
- 会话自举（每项独立 spec，断点可恢复）
- 成本递减（前项结论复用到后项）
- 诚实边界（全 v0.1/指针式/待 Phase 1/实例化非验证）

## 第七章 诚实边界

1. 本规范是部署规范（工程层），不持判断权归属/不可逆决策红线/验收最终授予（在五局 goal-keeper 不可委托内核）。
2. v0.1 草案，工程规格依赖真实运行环境（模型/硬件/CI/存储/团队），给选项+判据+试点，不硬编码。
3. 实例化非验证：每项须 Phase 1 试点校准才 active；实例化非验证（无一次完整运行证据）。
4. 指针式：所有数字（并发/预算/上限/TTL/频率）以试点注册表为准，不预设。
5. 与五局关系：本规范是五局治理性基础设施要求的工程落地，不替代五局治理规范；治理性要求（不可委托内核/价值函数人属/判断带宽/Pre-Verified≠Verified）仍由五局持有。

## 附录 A 敌意审查继承与本域新增风险

继承五局敌意审查修复要点（判定者不得自免审/批准即登记/固化分权/政策层入变更门/自动化=会话内 checklist/对己不豁免失效预演）。本域新增已识别风险：
1. **工程规格未校准即用**（v0.1 草案当 active 用）→ 必过 Phase 1 试点复现≥2+fresh 审查
2. **数字硬编码**（并发/预算/上限预设）→ 指针式，以试点注册表为准
3. **治理性要求下沉**（工程层越权持判断权）→ 本规范不持不可委托内核，裁决在 goal-keeper
4. **形态升级不可逆**（单机→云后回不去）→ 升级用 flag-with-ttl 可回退
5. **监控越权自动处置**（监控栈自动改产物）→ 监控只读+告警上浮选择题，处置在人
