# 开发局 development-bureau：开发组织的元组织
## ——独立可执行规范 v0.2

> **本文件三行说明**
> ① 给人类（goal-keeper）：你只需要在三个触点出场（§5.4）——不可逆实例化签字、敌意审查判决、例外路由/HALT。其余交给门禁与六态里程碑。
> ② 给 AI 会话（开发协调官）：会话开始先自举（§5.3）；Locked 需求包进来先过可执行性预检再分解（§5.1）；进度用六态里程碑推进、禁百分比（§5.5）；你**单写者**，实现者只写自己闭包。
> ③ 状态：v0.1（首个 standalone；此前设计阶段 G-S11 缺、实现折叠于生产局一行）。零外部依赖，本文件可独立运行。

## 出版说明

本规范是通用元组织（formation-bureau）在**软件开发的执行面（设计 + 实现）**的特化：其上游为《AI 原生组织理论》（§38 分解、§39 需求保真、操作手册六步路径第 1–3 步）。特化原则：通用机制（目标闸/缓存/门控/治理/学习）不变，生成器内容替换为执行面构件（设计三元组/闭包实现/flag 编译/开源基座）。**运行时监督机制（六态状态机/R/I 分级验收/监督三通道/升级链/监督负载）内联于本规范 §5.5 与条款 D7/D11/D17–D19**——与过程管控协议提案 v0.3 同源（该提案为理论正文 v1.1 候选，溯源见附录 C，非运行依赖）。

**诚实边界**：①本规范是实例化不是验证——开发局尚无一次完整运行证据，首次运行即第一批读数；②执行面未覆盖多跳委派（平台-开发商-客户三明治，理论 §50 自认）；③判断质量只能防流失不能凭空造；④路由表与门禁强度未经 Phase 1 校准，路由表标 candidate。理论再版后须复核本文件。

**G-S11 消解说明**：生产局挂账 G-S11"设计阶段独立规范缺位"由本规范补上（设计三元组见 §10.2、设计审查门见 C4）；实现阶段从生产局"临时开发组织 + 六态里程碑"一行展开为本规范的完整实现协议（§5.5–§5.7）。

## 第一章 定位：开发局是什么

### 1.1 核心重述

开发局是**执行面**：它把 Locked 需求包（想象侧的冻结决策集）变现为运行系统，接受测试质检局（判定侧）的测量。三段对偶：

```
需求局（想象侧）──Locked 需求包──→ 开发局（执行面）──构建产物──→ 测试质检局（判定侧）
   静态契约                               动态过程                           静态验收
```

需求局回答"造什么"、测试质检局回答"怎么判"、**开发局回答"怎么造、造到哪、花多少"**——执行面是唯一带时间箭头的环节，质量/进度/成本三属性都只在这里发生。

### 1.2 元策略

最优实现路径不存在，存在的是最优元策略：**生成（枚举候选实现）+ 门控（词典序判定：先挡死再优化）+ 收敛（每次对抗买信息，反馈缩小空间）**。实现不是被"写"出来的，是被生成和筛选出来的。

### 1.3 常设与临时

永久存在的只有治理席位、执行缓存（闭包库/契约库/构件库/flag 库/缺陷库）、门禁、学习引擎——**没有常设执行岗**。每次开发任务按目标成军临时开发组织，验收即解散；判定类角色（verifier/敌意审查员）每次新开无共享上下文实例。

### 1.4 不是什么

- 不是项目管理办公室（无常设执行岗，阶段组织按目标成军即散）；
- 不是"把需求丢给 AI 全自动写完"（不可逆实例化签字 + Verified 永远在人）；
- 不是流程越重越好（轻量通道存在，多数小改动该走它）；
- 不是覆盖率越高越好（六态禁百分比，Artifact 才是跃迁依据）。

## 第三章 Goal 治理（开发局自身的 Locked Goal）

**Goal：对经委托进入的 Locked 需求包，可靠地产出通过测试质检局验收的运行系统，并使同类目标的实现成本递减，且实现永不篡改需求。**

**可判定验收条件（AC，缺一不算完成）**：
1. 可执行性预检通过（AC 至少判定级 + 双签已过）；
2. 设计三元组落盘（闭包分解图 + 界面合同 + 组织设计）且过设计审查门；
3. 构建产物过六态里程碑（零百分比声明）且自检构成 Pre-Verified；
4. 构建产物交接测试质检局验收（发布门契约+灰度、终审 Verified 均在判定侧）；
5. 学习闭环闭合：缺陷逃逸分账 + 缓存固化或显式不固化留痕 + 成军三字段记账。

**负例（做了不算达成）**：仅对话结论不落盘；跳过设计审查直接实现；修改 AC/需求（差异走分诊通道）；状态虚标（"90% done"）；未过发布门交付；Verified 由 AI 自授。

**优先级**：判据正确性 > 判断带宽节约 > 交付速度。

## 第四章 六大组件

### C1 执行闸（受理前台）
Locked 需求包进入 → **可执行性预检**（AC 至少判定级 + 双签已过）→ 成军前查重 → 通道初判（轻量/全量，§5.2）→ 分类结论经 goal-keeper 确认。硬约束：落盘记录进入时间戳；存在性断言标读取时点。
*消解*：不可判定的需求包流入实现；Type III 后门（能做什么就做什么）。

### C2 执行缓存（五库）
- **闭包库**：历史决策闭包分解先例（同类目标的闭包图种子）；
- **契约库**：确认的契约测试与不变量（跨项目复用）；
- **构件库**：可复用的实现构件/模块模板；
- **flag 库**：可逆维度的开关清单（带 TTL 与清理责任）；
- **缺陷库**：历史缺陷分诊先例（同类缺陷第二次不交学费）。

读写协议：单写、子组织只读；固化双门（第二次独立复现 or fresh 审查，active 化裁决在 goal-keeper）+ 同域冲突检查 + 每条带复验条件。
*消解*：同类缺陷第二次交学费；闭包图从零设计；契约腐化。

### C3 执行生成器
**设计三元组引擎**（闭包分解：按决策闭包切 + 接口最小化；界面合同：契约测试 + ACL + 绞杀者 + flag 架构；组织设计：开发 AOOS + 降级拓扑预置）＋ **闭包实现引擎**（单写者 + 最小权限 + 自检）＋ **探针/契约运营器**（特征测试/影子流量/回放/并行跑）。
*消解*：闭包切错；契约不完备；依赖暗雷。

### C4 门控（执行面门禁）
**设计前置审查门（v0.2 升为硬 Gate）**：设计三元组产出物——闭包图（决策闭包分解 + 接口最小化）／接口契约（契约测试 + ACL + 绞杀者 + flag 架构）／降级拓扑（开发 AOOS + 降级拓扑预置）——为进入闭包实现引擎的硬前置；fresh 敌意审查不可逆预演/依赖分析前置/契约完备/降级拓扑预置/编排者失效预演，未过不得进入闭包实现引擎（C3 内部序：**设计三元组引擎 → 本门 → 闭包实现引擎**）／**六态里程碑**（禁百分比，状态由 Artifact 跃迁，内联定义见 §5.5）／**自检构成 Pre-Verified**（开发者自检 + 集成员）。**发布门与终审门在判定侧（测试质检局）**——本局交付构建产物 + 自检，交接后由测试质检局跑发布门（契约+灰度）与终审门（Verified）。
*消解*：状态虚标；不可逆预演缺失；后置质检（后置归判定侧门禁）；跳设计直奔实现（v0.2 增，见 E11）。

### C5 治理层
**不可委托内核**（goal-keeper：不可逆实例化签字/敌意审查判决/例外路由/HALT）；**单写者 + 最小权限**（每个产物单一写入者；角色最小权限；判定类派发须人确认）；**验证额度**（信任三段制适用代码库：信任模块抽样/变更模块全量/抽样率显式）；**判断带宽总账**（多目标并行时监督负载合并记账，超限先降并发不降标准）。
*消解*：并发写语义漂移；治理链漂移；终审成本线性上升。

### C6 学习引擎
**缺陷逃逸分账**（每个缺陷发生层/发现层/逃逸距离）→ **三症状分诊回灌**（发散/遗漏/漂移各归因，§5.7）→ **缓存固化**（闭包/契约/构件/缺陷四库双门固化）→ **实现成本记账**（成军三字段：耗时/复用构件/新固化）→ 注册表同步。
*消解*：同类缺陷重复；执行面经验流失；成本递减不可观测。

## 第五章 运行时

### 5.1 双层循环

**外层（常设，开发协调官主循环）：**

```
Locked 需求包进入（goal-keeper 委托；C1 记进入时间戳）
 → C1 执行闸：可执行性预检 / 查重 / 通道初判（人确认分类）
 ├─ 轻量通道：单 actor + 闭包 checklist + mini 自检 + 登记 + 校准 → 结束
 └─ 全量通道：
    C2 缓存查询（闭包库/契约库命中 → 短路）
    → C3 设计三元组引擎：闭包分解 + 界面合同 + 组织设计
    → C4 设计审查门（fresh 敌意审查）→ 不可逆实例化签字
    → 闭包实现引擎：单写者 + 六态里程碑推进 + 自检（Pre-Verified）
    → 交接测试质检局（发布门 + 终审门在判定侧）
    → C6 逃逸分账 + 固化 + 记账
    → 开发组织解散 → 缓存增值 → ↺
```

**内层（临时开发组织）**：标准 AOOS 循环（按闭包实现→自检→集成→门禁）。开发协调官只持治理钩子——例外路由、验证额度、安全停机——不干预 HOW。

### 5.2 路由决策表 v0.1（candidate，首次实测后重估）

| 目标性质 | 通道/组织形态 | 关键门 |
|---|---|---|
| 单点小改动（可逆、无设计争议） | 轻量：单 actor + 闭包 checklist + mini 自检 | 人确认分类 |
| 新产品/新模块 | 全量：设计三元组 + 开发组织 + 敌意审查 | 设计审查门 + 六态 + 发布门 |
| 存量平台升级 | 探测双模式（探针/契约）→ 契约界面先行 | 契约测试 + 探针可逆 + 试点 |
| 涉及不可逆承诺（定价/API/schema） | 设计不可逆实例化签字 + 契约 + 属性测试 | 双签 + goal-keeper 逐项签字 |
| 开源基座定制 | fork diff 最小 + 扩展点/ACL 收编 | 契约守护 + 定期合并窗口 |

### 5.3 会话自举协议

开发协调官每次会话按固定清单恢复状态：①注册表（在航/待批开发组织）；②五库缓存；③本规范；④未闭合的 DecisionRecord 与六态里程碑当前态。goal-keeper 不在线 = 停于待批，安全停机，无超时自动越权。

### 5.4 人类触点（仅三个）

| 触点 | 做什么 | 为什么不可委托 |
|---|---|---|
| 不可逆实例化签字 | 设计的不可逆技术决策（schema/API/定价）逐项拍板 | 不可逆 + 价值函数人属 |
| 敌意审查判决 | 设计审查门的判决（ACCEPT/notes/REWORK） | 独立判定（I-DISC） |
| 例外路由/HALT | 实现阶段阻塞级异常上浮裁决 | 停止优先于假验证 |

### 5.5 六态里程碑与过程监督（内联定义，D7/D11/D17–D19）

进度用六态状态机推进，状态只能由 Artifact 跃迁（禁百分比）：

```
Open ──agent 预判──→ Pre-Verified（待核，终判权在人）
 │ │                    R 类：入抽样池 → 人工判定 → Verified / 退回 Open
 │ │                    I 类：不经此态（直接人工全量判定）
 ├──────→ Blocked ──解除──→ Open
 │            └─滞留 > T_b─→ 升级链（下述）
 └──────→ Cancelled（终态，附撤销决策记录）
```

四出口映射：Reject→Cancelled；Rewrite→Open（新 AC）；Rollback→Open（回退重开）；Halt→组织级 Safe Halt。

**两条铁律**：①状态只能由 Artifact 跃迁——"90% done"是声明不是跃迁；②Pre-Verified ≠ Verified——未被人工抽中的 Pre-Verified 永远不是 Verified，其产物可被引用但引用链标注"待核"。

**R/I 分级验收（D11）**：
- R 类（可逆）：全部产物可经既有回退机制以有界成本撤销 → agent 预判 + 委托人抽样复核；
- I 类（不可逆）：触及不可委托内核，或状态不可恢复且损失无界 → 强制全量人工判定，无抽样豁免；
- 分级表是计划产物，委托人在批准时逐条确认；既不满足 R 也不满足 I 的保守归 I。

**监督三通道（D17）**：事实通道（拉，读 Artifact）/ 例外通道（推，仅四类事件打扰委托人：阻塞级缺陷 / 停机 / 不可逆决策 / 终审）/ 抽样通道（R 类定期抽样，目标对齐 + 产出质量双维）。

**升级链时限（D18）**：Blocked 滞留超 T_b（默认 72h）→ 编排者处置窗口（24h）→ 委托人必处理队列（72h）→ 超时组织自动 Safe Halt（委托人的沉默是停止信号，不是继续信号）。

**监督负载科目（D19）**：I 类判定数 × 单位成本 + R 类抽样数 × 单位成本，以人工判定分钟数入账；每门开设须写明预期 R_h 成本，带宽不足先收窄作业面、不降抽样率。

**监督活性**：Override Rate 落在 [下限,上限] 区间（趋零 = 监督已死，超上限 = 越权）；连续 K 周期零例外触发反向哨兵审查（人的沉默是危险信号，不是成功信号）。

### 5.6 存量与开源基座实现协议

- **探针优先**：行为假设化地图（[已知/推断/未知]）+ 探针队列；读码推演不构成锁定依据；
- **契约界面**：动哪个区域先立契约测试；自定义逻辑入防腐层 ACL；替换走绞杀者；
- **开源上游漂移**：定制收进扩展点/插件/ACL，fork diff 压最小，上游合并走定期窗口，合并前跑契约测试。

### 5.7 实现三症状分诊（16 号收编）

实现侧 AI 的三种病，各吃各的药：

| 症状 | 机制 | 对症机制 |
|---|---|---|
| **发散**（做了没让做的、越做越多） | 有生成无收缩；三件套缺负例 | 锁定负例（做了不算达成清单）；停止规则显式化；判断带宽预算 |
| **遗漏**（该做的悄悄没了） | 裂缝折叠 + 多跳衰减 | 五道裂缝问卷；AC 可执行化；理解验收 T1–T4（动手前复述） |
| **漂移**（做着做着目标变了） | Intent Loop 无运行时锚 | Artifact-only 目标传递；例外上浮；Goal Drift Monitor；会话分离 |

**分诊纪律**：三种症状吃错药互相加重——对发散加"多沟通"加重漂移、对漂移加"多文档"加重遗漏、对遗漏加"人肉逐条对"撞带宽红线。先辨症状，再下药。**症状常混合出现，先识别主导症状**，避免对次症状用药反而放大主导症状。

### 6.1 政策继承块

### 6.2 组织权限（白名单）

- **开发协调官**：写注册表/五库/设计三元组/构建产物目录；派发（判定类须人确认）。不含：改 AC/需求、授 Verified。

## 第七章 死法预演（十条，词典序）

| # | 死法 | 机理 | 对策 |
|---|---|---|---|
| E1 | 分解过度 | 决策闭包过小，门比活多 | 门数预算化：每门写明预期 R_h 成本 |
| E2 | 闭包切错 | 接口爆炸/竖井，跨区开会才能决策 | 决策闭包分解 + 接口最小化；切完需跨区开会即切错 |
| E3 | 契约不完备 | 负例缺，黑盒不确定性回流 | 契约测试入 CI 硬门 + ACL 纪律 |
| E4 | 状态虚标 | "90% done"是声明不是跃迁 | 六态里程碑禁百分比 + Artifact 跃迁 |
| E5 | 探针污染生产 | 探针自身不可逆 | 探针全程可逆（影子/回放/只读） |
| E6 | 上游漂移击穿 | 开源基座更新击穿定制层 | fork diff 最小 + 契约守护 + 定期合并窗口 |
| E7 | 发散（有生成无收缩） | AI 扩张强收缩弱，做了没让做的 | 锁定负例 + 停止规则 + 带宽预算 |
| E8 | 遗漏（裂缝折叠） | 该做的悄悄没了，多跳衰减 | 裂缝问卷 + AC 可执行化 + T1–T4 |
| E9 | 漂移（Intent Loop 无锚） | 目标活在对话史里被稀释 | Artifact-only + 例外上浮 + 会话分离 |
| E10 | 单写者违反 | 并发写造成语义漂移 | single-writer 政策 + 最小权限 |
| E11 | 跳设计直奔实现（v0.2 增） | C3 闭包实现引擎先于设计三元组产出，设计散落事后补（AI 扩张强收缩弱，直奔实现） | C4 设计前置审查门硬前置：设计三元组（闭包图+接口契约+降级拓扑）未产并过审，不得进入闭包实现引擎 |

## 第八章 度量与诚实边界

**实现四字段**（每次记注册表行，按通道分层）：实现耗时（进入时间戳→Verified）、缓存复用构件数（闭包/契约命中）、本次新固化数、逃逸距离分布。递减性 = 四字段时间序列，按通道分层统计。

**执行面仪表**：缺陷逃逸距离分布（各门禁有效性仪表）+ 三症状分诊计数（发散/遗漏/漂移各自命中率）+ 六态跃迁完整性（有无百分比声明残留）+ 契约覆盖度。

**诚实边界**：实例化非验证（无一次完整运行证据）；路由表/门禁强度未经 Phase 1 校准；多跳委派不覆盖；判断质量只能防流失不能凭空造。不做硬编码计数陈述——指针式（以注册表为准）。

## 第九章 使用手册（独立运行）

### 9.1 冷启动清单

①一个人类（愿在三触点出场）；②一个 AI 会话（能读写文件、能派 fresh 子代理）；③四个文件区：注册表/五库缓存（初始可空）/本规范/未闭合 DecisionRecord；④政策块直接抄 §6.1。

### 9.2 一个目标的完整走法

1. **进入**："按开发局处理：<Locked 需求包名>"。
2. **C1**：可执行性预检 + 查重 + 通道初判 → 人确认分类。
3. **轻量**：单 actor 过闭包 checklist → mini 自检 → 人批准 → 登记 → 结束。
4. **全量**：设计三元组（闭包/合同/组织设计）→ 设计审查门（fresh 敌意）→ 不可逆实例化签字 → 闭包实现（单写者 + 六态）→ 自检 Pre-Verified → 交接测试质检局（发布门+终审门）。
5. **回填**：逃逸分账 → 固化判定（双门）→ 四字段记账 → 解散。

### 9.3 人类指南（一页）

- 三触点见 §5.4；红线：不替 AI 写代码（它比你快），不让 AI 做你的终审（它的"完成"是 Pre-Verified）。
- 你会收到的请求只有三类：不可逆签字/敌意审查判决/例外 HALT。其余时间不被打扰即系统健康。
- 长期不在线：系统停于待批，安全停机。

## 附录 A 敌意审查继承与本域风险

继承成军局 18 处击穿修复（判定者不得自免审/批准即登记/固化分权/政策层入变更门/自动化=会话内 checklist/对己不豁免失效预演）。本域新增已识别风险：

1. **闭包切错**（E2）——接口爆炸/竖井 → 决策闭包分解 + 接口最小化；
2. **状态虚标**（E4）——"90% done"声明 → 六态里程碑禁百分比；
3. **三症状吃错药**——发散/遗漏/漂移各吃各药，吃错互相加重（§5.7）；
4. **R-Hyrum**——行为已被验证而未回写需求 → 隐性需求固化 → 回写纪律不可省（证据回写需求、不篡基准位置）；
5. **单写者违反**（E10）——并发写语义漂移 → single-writer 政策。

## 附录 B 术语速查

**执行面**：把 Locked 需求包变现为运行系统的动态环节（设计+实现）。**Locked 需求包**：需求局产出、开发局的输入——三件套（可判定 AC + 负例 + 优先级）+ 五道裂缝（边界/例外/主体/代价/禁区）+ 维度清单。**三问**：决策前置三问——维度（怎么判成功）/死法（怎么死）/可逆性（能否有限成本回退）。**双签**：需求局起草 AC × 测试质检局签发可执行化判定，双签才锁定。**T1–T4 理解验收**：动手前复述（独立复述/假设清单/边界反问/判别独立），复述即暴露遗漏。**设计三元组**：闭包分解图 + 界面合同 + 组织设计。**决策闭包**：做完整即可判定的最小单元。**六态里程碑**：Open/Pre-Verified/Verified/Blocked/Cancelled，禁百分比。**三症状**：发散/遗漏/漂移。**flag 参数化**：可逆维度的运行时表示。**绞杀者**：新旧并存、按路由渐进替换。**AOOS**：临时组织的声明式组建骨架（Goal/Actor/任务分解/DecisionRecord/Runtime Loop/终审栏/事后校准）。**R_h**：人工判定成本（判断带宽的单位支出，见 D19 监督负载科目）。**Pre-Verified/Verified**：AI 自检结论/人类授予的最终验收。
