# 基于 AI-native 的知识沉淀流程规范

## ——独立可执行规范 v0.1

## 出版说明

本规范是 AI 原生组织理论五局元组织规范知识沉淀机制的**端到端流程规范**：把机制分析研究笔记 §三的生命周期结论（运行产出→校准回填→固化双门→candidate→active→复验→命中短路/失效淘汰→↺）落成**可执行规范**，串起五局各覆盖的本局片段。

**分层关系**：机制分析是研究笔记（来源/方法/发现/局限/结论，非规范）；五局各覆盖本局知识沉淀片段；本规范是**流程规范**，把 5 阶段端到端串成可执行，不替代五局治理规范（不可委托内核/价值函数人属/判断带宽仍由五局持）。

**适用**：任何"人类 + 可派子代理的 AI 会话"组合运行知识沉淀全流程时，用本规范确定 5 阶段机制+阶段交接触发+跨局流转。

**依据**：机制分析 §三生命周期 + 四性 + 核心指标；五局 C2/C6；部署规范 07 产物存储。

## 第一章 定位：流程规范 vs 研究笔记 vs 五局片段

- **机制分析**（研究笔记）：给生命周期 + 四性 + 核心指标的**结论**，非可执行条款。
- **五局规范**：各覆盖本局知识沉淀片段（成军三层/需求四库一图/开发五库+D15/测试质检五库/生产反馈流），无端到端串联。
- **本规范**（流程规范）：把 5 阶段端到端串成**可执行条款**+阶段交接触发+跨局流转，是五局知识沉淀的流程总入口。

本规范只定"5 阶段怎么跑+阶段交接+跨局流转"，**不持**判断权归属/不可逆决策红线（在五局 goal-keeper）。

## 第二章 5 阶段端到端流程

```
【产生】运行产出 → 校准回填（DecisionRecord 事后校准：预测×结果×意外）
   ↓ 触发：产出落盘 + DR 校准回填完成
【验证】固化判定（双门：第二次独立复现 OR fresh 审查）+ 冲突检查 + I-DISC
   ↓ 触发：双门过 + 冲突检查通过
【沉淀】进缓存（candidate→active）+ 双账本分层 + 缓存条目 schema + 单写者
   ↓ 触发：active 化（裁决在 goal-keeper）
【应用】命中即短路（D15）+ applicability/negative_example 边界 + 跨项目/跨组织
   ↓ 触发：复用时 recheck_condition 检查
【升级】带有效期复验 + 失效即淘汰 + Surprise Rate + 成本递减 + 行为可验证改变（T10）
   ↓ 触发：升级/淘汰触发新一轮产生
   ↺（闭环）
```

## 第三章 5 阶段可执行条款

### 阶段1 产生

**机制**：运行产出 + 校准回填（DecisionRecord 事后校准：预测×结果×意外）。
**触发产出**：DecisionRecord（三问事前+预测+事后校准）+ Surprise Rate 信号。
**四性**：准确性（一切结论带锚点+禁记忆+读取时点+会话分离+数据锚点）。
**条款**：
1. 每次运行产出落盘（不落盘不算完成，§187）。
2. DecisionRecord 事后校准必填（预测×结果×意外三栏）。
3. 引用外部材料抓取核实禁凭记忆（no-memory-citation）。
4. 存在性断言标注读取时点（existence-claims-timestamped）。
5. 探索用 fresh 子代理独立上下文（R9 会话分离）。
6. 假设台账回填必附数据锚点（防事后合理化）。

### 阶段2 验证

**机制**：固化双门（第二次独立复现 OR fresh 审查通过）+ 冲突检查 + I-DISC。
**触发产出**：candidate→active 候选 + 双门证据。
**四性**：正确性（防 D4 学习污染）。
**条款**：
1. candidate→active 必满足双门之一：第二次独立复现（无共享上下文实例再做一次结果一致）OR fresh 审查通过（无共享上下文审查员攻击过）。
2. active 化裁决在 goal-keeper（人类），不在 AI（固化是治理节点非技术动作）。
3. 固化前做同域条目冲突检查（cache-conflict-check，防新旧矛盾并存）。
4. I-DISC（R8）：判别器不得是生成候选同一模型/会话；AI 自检只构成 Pre-Verified，Verified 人授（R13）。
5. negative_example 必填（每条带"何时不适用"）。

### 阶段3 沉淀

**机制**：candidate→active + 双账本分层 + 缓存条目 schema + 单写者。
**触发产出**：active 缓存条目（入对应局 C2 库）。
**四性**：有效性（双账本+命中率优先+外部判别器破回声）。
**条款**：
1. 双账本分层：蒸馏层（patterns/协议文本，可独立交付 P-015）+ 回放层（运行记录/DecisionRecord，保留分支结构支持反事实评估）；禁止用蒸馏层覆盖回放层。
2. 缓存条目 9 字段 schema 落盘：id/layer/content/source_event/applicability/negative_example/status/reproduction_count/recheck_condition/read_at。
3. 单写者：协调官写，子组织只读（R8）；并发写走 worktree 隔离+固化双门（见部署规范 01）。
4. 缓存分层按局：成军三层（pattern/policy/component）/需求四库一图/开发五库/测试质检五库。
5. 命中率优先于数量（未命中即生成是常态，C3 生成器恒在场）。
6. 定期外部判别器（fresh 审查/异模型复核）打破回声室。

### 阶段4 应用

**机制**：命中即短路（D15）+ applicability/negative_example 边界 + 跨项目/跨组织。
**触发产出**：复用构件数（成本递减四字段之一）。
**四性**：有效性（防 D1 缓存僵化：违反适用边界复用）。
**条款**：
1. 同局下次同类目标 C2 查询命中即短路（D15 第二个同类目标免费起点）。
2. 复用必带 applicability（适用边界）+ negative_example（何时不适用）+ recheck_condition（复验条件）三边界守门。
3. 跨项目复用：契约库（开发局 §111/测试质检局 §122，"一次确认终身复用"）+ 构件库。
4. 跨组织复用：pattern 层（成军局 §105 跨组织协议）。
5. 跨领域复用：领域知识（判据/闭包/缺陷）**不跨**（防 D1）；跨的是 pattern/契约/构件（元协议层）。
6. 跨独立 goal-keeper/仓库：走外部锚 I-21 + 本地复现过双门，不共享 active 写权（见跨组织复用 spec）。

### 阶段5 升级

**机制**：recheck_condition 复验 + 失效即淘汰 + Surprise Rate + 成本递减 + 行为可验证改变（T10）+ 行业先验四层 + flag TTL。
**触发产出**：失效淘汰出库 + 升级回写 + 成本递减四字段。
**四性**：时效性（防 D1 过期僵化）。
**条款**：
1. recheck_condition schema 强制字段，到期/触发条件必复核，不复核即不可信。
2. 失效即淘汰出库（不僵尸留存）。
3. Surprise Rate 驱动：零增益轮触发停止审查（R25，不 churn）。
4. 成本递减四字段记账：耗时/复用构件数/新固化数/Surprise，按通道分层防 Goodhart；指针式（§251）。
5. 行为可验证改变（T10）：沉淀完成标准是"下次行为变了没"，不是"存了多少"——存了行为没变=死库。
6. 行业先验四层制（硬约束/半强制/参考性/启发式，失效速度递增）+ flag TTL（防 flag 债务）+ 判据 TTL 复验（防 Goodhart）。
7. 升级/淘汰触发新一轮产生（↺ 闭环）。

## 第四章 阶段交接触发条件（统一明文）

| 交接 | 触发条件 |
|---|---|
| 产生→验证 | 产出落盘 + DecisionRecord 校准回填完成（预测×结果×意外三栏齐） |
| 验证→沉淀 | 双门过（独立复现 OR fresh 审查）+ 冲突检查通过 + goal-keeper 裁决 active |
| 沉淀→应用 | active 化（可被复用）；同局下次同类目标查询命中即短路 |
| 应用→升级 | 复用时触发 recheck_condition 检查；到期/触发条件即复核 |
| 升级→产生 | 升级回写或失效淘汰触发新一轮运行产出的校准回填（↺） |

## 第五章 跨局流转协议

- **pattern 层**（成军局 C2 §105）：跨组织复用经验协议，所有局可读。
- **契约库**（开发局 §111/测试质检局 §122）：跨项目复用不变量，"一次确认终身复用"。
- **跨局流转**：知识在某局 active 后，通过 pattern 层/契约库跨局可读；跨独立 goal-keeper 走外部锚 I-21 + 本地复现过双门（不直接共享 active 写权）。
- **不跨领域**：领域知识（判据/闭包/缺陷）按域就地固化不跨（防 D1）；跨的是元协议（pattern/契约/构件）。

## 第六章 核心指标与元原则

- **核心指标**：成本递减性（耗时/复用构件数/新固化数/Surprise 四字段时间序列，按通道分层防 Goodhart）——知识沉淀是否真发生的终极判据。
- **元原则**：学习的完成标准是未来行为可验证改变（T10）——存了行为没变=死库。
- **停止信号**：信息增益元原则（R25）——零 Surprise=无新信息可沉淀=空转，立即停。

## 第七章 Phase 1 试点

按 5 阶段顺序试点一个完整闭环：
- **probe**：跑一个目标，产 1 缓存条目走完产生→验证→沉淀→应用→升级→↺ 全流程。
- **判通过**：DR 校准回填完整 / 双门过+冲突检查 / 9 字段 schema 落盘+单写者 / 命中短路+三边界 / recheck 复验+失效淘汰+四字段+T10 行为改变+零增益停。
- **待 Phase 1**：阶段交接触发阈值/跨局流转频率/成本递减收敛点（指针式）。

固化条件：试点复现≥2 → candidate → fresh 审查 → active（裁决在 goal-keeper）。

## 第八章 方法自洽

本规范用知识沉淀流程自己的方法跑：每阶段产出落盘（不落盘不算完成）+ 双门验证（不自验）+ 双账本（蒸馏可交付+回放可追溯）+ 命中率优先（不狂存）+ recheck 防僵化 + 成本递减读数 + T10 行为改变判据 + R25 零增益停。

## 第九章 诚实边界

1. 本规范是流程规范（把 5 阶段端到端串成可执行），不持判断权归属/不可逆决策红线（在五局 goal-keeper）。
2. v0.1 草案，工程细节（存储后端/监控）依赖部署规范，给流程条款不给工程规格。
3. 实例化非验证：须 Phase 1 试点校准才 active。
4. 指针式：阶段交接触发阈值/跨局流转频率以试点注册表为准，不预设。
5. 与五局关系：本规范是五局知识沉淀片段的流程总入口，不替代五局治理规范；治理性要求（不可委托内核/价值函数人属/判断带宽/Pre-Verified≠Verified）仍由五局持。

## 附录 A 敌意审查继承与本域新增风险

继承五局敌意审查修复要点（判定者不得自免审/批准即登记/固化分权/政策层入变更门/自动化=会话内 checklist/对己不豁免失效预演）。本域新增：
1. **阶段交接跳过**（产生未校准就验证/未双门就 active）→ 阶段交接触发条件统一明文（第四章），未触发不得进下阶段
2. **跨领域复用领域知识**（判据/闭包/缺陷跨域）→ D1 缓存僵化；只跨元协议（pattern/契约/构件）
3. **只存不用**（沉淀不应用=死库）→ T10 行为可验证改变判据 + 命中率优先
4. **不复验**（active 后永不过期）→ recheck_condition 强制 + 失效淘汰
5. **蒸馏覆盖回放**（只留摘要丢轨迹）→ 双账本互不可替代，禁蒸馏层覆盖回放层

## 附录 B 术语速查

**知识沉淀流程规范**：5 阶段端到端可执行规范。**产生**：运行产出+DR 校准回填。**验证**：固化双门+冲突检查+I-DISC。**沉淀**：candidate→active+双账本+schema+单写者。**应用**：命中短路+三边界+跨项目/组织。**升级**：recheck+失效淘汰+Surprise+成本递减+T10。**双账本**：蒸馏层（可独立交付）+回放层（运行轨迹）。**固化双门**：独立复现 OR fresh 审查。**D15**：命中即短路，第二个同类目标免费起点。**T10**：行为可验证改变（沉淀完成判据）。**R25**：零增益即停。**四性**：正确性/准确性/有效性/时效性。**成本递减四字段**：耗时/复用构件/新固化/Surprise。
