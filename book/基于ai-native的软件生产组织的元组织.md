## 出版说明

本规范是通用元组织（formation-bureau）在**软件生产全程**的特化与总装：商业目标为根锚，需求局（想象侧）与测试质检局（判定侧）两个常设局，设计/实现阶段由开发局（standalone 独立规范 v0.2）承担，六道门禁贯穿。特化原则与需求域版一致：通用机制（目标闸/缓存/门控/治理/学习）不变，生成器内容替换为全程构件。

**诚实边界**：①全部构件未经一次端到端实测，首次运行即第一批读数；②理论自认"多跳委派无模型"——平台方-开发商-客户三明治结构暂不覆盖；③判断质量只能防流失不能凭空造；④各域已有更细的独立规范——需求域（需求局 v0.5）、开发域（开发局 v0.2）、测试质检域（测试质检局 v0.1）独立成 standalone 后，本文件为压缩总装版，精细操作以各域独立规范为准（在源仓库内）。**规范优先级：跨域冲突以更细的独立规范为准。**理论再版后须复核本文件。

## 第一章 定位：生产局是什么

### 1.1 元策略

最优生产流程不存在，存在的是最优元策略：**生成（探索候选）+ 门控（词典序判定：先挡死再优化）+ 收敛（每次对抗买信息，反馈缩小空间）**。生产局不"管理项目"——它运营这个元策略在五个阶段上的执行。

### 1.2 全程的三个重述（本规范的公理）

1. **需求确认是可能性空间的收敛**：一句话需求 = 缺决策非缺信息；商业目标 = 价值函数，**只能由承担后果者提供**；存量系统 = 组织缓存 + 认知债。
2. **需求与实现互相约束（互锁）**：想象空间靠决策消解不确定性，判定空间靠证据消解；AC 是两空间的界面协议；**不可测试的需求 = 未锁定的需求**。
3. **全流程质检 = 按失效面分级的拦截**：让每类错误在其最便宜的拦截层被买断；缺陷逃逸距离（发现层−发生层）是门禁有效性的仪表。

### 1.3 不是什么

不是项目管理办公室（无常设执行岗，阶段组织按目标成军验收即解散）；不是全自动流水线（七触点与终审永远在人）；不是流程越重越好（轻量通道存在，多数小目标该走它）；不是在找最优解（锁定的是停止规则触发时**足够好且可退**的解）。

## 第三章 Goal 治理（生产局自身的 Locked Goal）

**Goal：对经委托进入的商业目标，可靠地运营五阶段全流程（假设→锁定→设计→实现→质检→发布→回填），产出满足双保障的交付与证据闭环，并使同类目标的全程成本递减。**

**AC**：①假设台账挂接且按脆弱×值钱排序；②Locked 需求包双签（AC 至少判定级+负例+优先级）；③设计三元组过设计审查门（含不可逆预演与依赖分析）；④实现全程六态里程碑零状态虚标；⑤发布门双过（契约+灰度判读）且 Verified 由人授；⑥假设台账回填留痕（固化或显式不固化）+ 全程记账（成军三字段+逃逸分账+对抗三记账）。
**负例**：任何阶段以对话结论代替产物交接；跳过双签锁定；质检修改需求；未过发布门上线；学习环节无行为改变。
**优先级**：判据正确性 > 判断带宽节约 > 交付速度。

## 第四章 全程结构

### 4.1 总览：一锚、两局、三临时组织

```
┌──────────────────────────────────────────────────────────────┐
│               商业目标（根锚：goal-keeper 独占）                │
│           商业模式 = 模块化假设系统（假设台账 H1…Hn）            │
└──────┬─────────────────────────────────────────▲─────────────┘
       │ 价值函数/假设台账             灰度证据回填 │ T2 证伪（变更门）
┌──────▼───────────┐              ┌──────────────┴────────────┐
│ 需求局（常设·想象侧）│              │ 测试质检局（常设·判定侧）     │
│ 漏斗/判据工程/先验  │◄──AC 双签───►│ 门禁/证据账本/差异分诊       │
└──────┬───────────┘              └──────────────▲────────────┘
       │ Locked 需求包                          │ 证据包
┌──────▼───────────┐   设计交接   ┌──────────────┴────────────┐
│ 设计（临时组织）    │────────────►│ 实现（临时开发组织）          │
│ 三元组（§10.3）    │  AOOS+契约  │ 六态/单写者/flag/降级拓扑    │
└──────────────────┘             └───────────────────────────┘
```

**常设的只有两个局与根锚；设计、实现阶段由开发局（standalone v0.2）承担，非生产局内部临时组织。**

### 4.2 五阶段身份表

| 阶段 | 所有者 | 输入 | 输出（Artifact） | 出口门禁 | 人类触点 |
|---|---|---|---|---|---|
| 商业 | goal-keeper | 市场信号/愿景 | 假设台账+价值函数声明 | 假设受理门（三问+Status-Quo） | 商业终审 |
| 需求 | 需求局 | 假设台账+一句话需求 | Locked 需求包（§10.2） | **锁定门=可测试门（双签）** | 通道确认/L1 决策/L3 选择/锁定批准 |
| 设计 | 临时设计组织 | 需求包+存量假设化地图 | 三元组（§10.3） | **设计审查门**（fresh 敌意：不可逆预演/依赖前置/契约完备/降级拓扑预置） | 不可逆实例化签字 |

| 质检 | 测试质检局 | AC+构建+灰度数据 | 证据包（§10.5） | **发布门**（契约+灰度判读）+**终审门**（Verified 人授） | 灰度结果认可 |

## 第五章 运行时

### 5.1 主循环

```
商业目标进入（goal-keeper 委托；记进入时间戳）
 → 假设受理门：三问过目标 / Status-Quo 对照 / 假设台账建档
 → 需求局：C1 通道判定（人确认）→ 轻量通道【单actor+裂缝checklist+mini三件套】
   或 全量【存量：测绘/探测双模式→漏斗 L0–L3→门禁】
 → 锁定门：需求局起草 AC × 测试局签发可执行化判定 → 双签 → goal-keeper 批准（批准即登记）
 → 设计：三元组生成 → 设计审查门（fresh）→ 不可逆实例化签字
 → 实现：开发组织按 AOOS 成军 → 六态里程碑推进（例外路由/HALT 上浮）
 → 质检：差异四类分诊 → 发布门（契约+灰度）→ 终审门（人授 Verified）
 → 回填：假设台账裁决 → 缓存固化（双门）→ 全程记账 → 阶段组织解散
 → ↺（缓存增值，下一目标更快）
```

### 5.2 三条贯穿线

**正向流**：只认产物不认对话——每个交接点是 Artifact，不是会议。**分层反馈流**：每类错误退回发生层（缺陷→实现；AC 歧义→判据工程降级链；契约漏洞→设计审查门；需求证伪→T2 变更门人裁决→再锁定；假设证伪→商业模式修正）。**治理触点线**：七个触点（§5.7），其余靠门禁与例外路由。

### 5.3 各阶段协议速查

- **需求**：五层漏斗（L0 ≥2 fresh 枚举员并行维度展开→L1 不可逆维度人主导→L2 ≤3 差异候选→L3 并排原型构造偏好→L4 灰度真值）；行业先验三角色（P7）；判据工程流水线（§10.2 规程框）。
- **设计**：闭包分解（做完整即可判定的最小单元+接口最小化）；界面合同（契约测试+ACL+绞杀者+flag 架构）；组织设计（开发 AOOS+降级拓扑预置）；L1 不可逆维度的技术实例化。
- **实现**：单写者+最小权限；过程产物四层（进度可死状态不可死）；六态里程碑——状态只能由 Artifact 跃迁，"90% done"是声明；可逆维度编译为 flag；开源基座走 fork diff 最小+定期合并窗口。
- **质检**：AC 可执行化（判定级→验收测试/方向级→对比测试/度量级→灰度统计）；差异四类分诊（实现偏离→改实现｜需求歧义→回流判据工程｜环境失真→测试局自校测量【加探针/影子流量】｜需求证伪→T2 变更门）；证据账本（缺陷台账/覆盖度地图/灰度读数/逃逸分账）。

### 5.4 拦截经济学（全流程质检的本质）

| 失效面 | 典型错误 | 最便宜拦截层 | 最贵发现层 |
|---|---|---|---|
| 理解面 | Type III、判据代拟、AC 评价性 | 可测试门（锁定双签） | 灰度 |
| 分解面 | 闭包切错、契约不完备 | 设计审查门 | 并行跑/生产 |
| 执行面 | 缺陷、状态虚标 | 六态+持续验证 | 发布门 |
| 环境面 | 测试过生产死 | 探针/影子流量 | 生产 |
| 判定面 | 弱断言、用例回声、篡位 | 独立性+负例否决权 | 无（最后防线） |

**逃逸分账**：每个被发现的错误标注发生层与发现层，逃逸距离=差——分布是各门禁的仪表；某门逃逸距离系统性变长=该门 Goodhart 化（在过门不在拦截）。

### 5.5 震荡的全程管理：多级坐标下降

震荡 = 单位成本信息增益 ≤ 0 的循环。五对阶段各有一条互锁与切换协议；**任一时刻只动一侧**。切换触发器：**T1 不可达**（能力/物理/成本实测失败→证据回写→人重决策→再锁定）｜**T2 证伪**（L4 与 AC 冲突→变更门人签；行为已被验证则**回写需求不可省**）｜**T3 空转**（同一冲突 ≥2 轮无新锚点→**分解优先**：已验证子集锁死进契约+争议子集 spike/降级——反复震荡常意味着需求不可行/不自洽或验收测错对象；分解后仍空转才升级人裁决，不切换基准）。辅助仲裁轴（验证状态）：需求已验→修实现；行为已验→回写需求；都未验→先补验证（买信息）。铁律：切换必以再锁定/再签发结束——基准真空（双向同时动）是系统最差状态。根锚永远=商业目标；**实现只是可观测性更高、置信度来自验证状态**——把未验证实现扶正为基准触发 Hyrum 效应（一切可观测行为含 bug 被依赖成隐性需求），故证据可改需求内容、不能篡基准位置。健康震荡三判据：不可逆集合单调缩小/幅度与 Surprise Rate 衰减/每次重开有台账锚点。

### 5.6 会话自举协议（无守护进程；一切"自动"=会话内 checklist 项）

生产协调官每次会话按固定清单恢复状态：①注册表（在航/待批各阶段组织）；②缓存（判据库/维度库/异常库/假设库/依赖图）；③本规范；④未闭合的假设台账与 DecisionRecord 项。goal-keeper 不在线=停于待批，安全停机，无超时自动越权。

## 第六章 治理

### 6.1 政策继承块（所有阶段组织自动继承；按域分组）

**基础**：三问决策前置；一切产出落盘（不落盘不算完成）；只认产物不认对话；禁止不可逆破坏性操作；存在性断言标注读取时点；成军前查重、批准即登记；会话分离（探索独立上下文+产物落盘）。

```yaml
policies:
  # 需求域
  - id: no-criteria-by-proxy        # 判据代拟禁令
  - id: no-evaluative-ac            # AC 禁评价性词；至少判定级；负例先于正例
  - id: fissure-gate                # 五道裂缝逐条闭合或显式留白归因
  - id: hypothesis-ledger-hook      # 需求条目必挂商业假设，否则不得锁定
  - id: ground-truth-is-l4          # 商业假设终裁只认灰度/真实用户证据
  - id: industry-prior-roles        # 合规入禁区/先验标环境前提/SOTA入差异化矩阵；特异清单必产
  - id: prototype-before-lock       # 涉偏好且可承担成本的需求未过 L3 不得锁定
  # 存量/设计域
  - id: probe-over-mapping          # 禁把完整测绘当改动前置；禁以推演为锁定依据
  - id: contract-as-interface       # 动存量先立契约测试；自定义入防腐层；替换走绞杀者
  - id: flag-with-ttl               # 可逆维度优先编译为带 TTL 开关；变动经开关与变更门
  - id: irreversible-drill          # 设计审查必含不可逆预演与依赖分析前置
  # 质检域
  - id: discriminator-no-amendment  # 判别器无修宪权：改测量自由，改 AC/需求零自由
  - id: case-author-independence    # 验收用例作者≠实现者（I-DISC）
  - id: release-double-gate         # 发布门=契约+灰度判读双过，缺一不放行
  - id: escape-distance-accounting  # 每个被发现错误标注发生层与发现层（逃逸分账必记）
  # 全程
  - id: anchor-is-purpose           # 根锚=商业目标；证据不得篡基准位置
  - id: relock-after-switch         # 任何切换以再锁定/再签发结束，禁止基准真空
  - id: oscillation-type-gate       # 不可逆反复必升级；无新证据摇摆 ≤2 轮
  - id: info-gain-ledger            # 每轮对抗记成本/淘汰候选数/新增锚点数；零增益触发停止审查
  - id: sampling-rate-explicit      # 信任三段制的抽样率显式设定
  - id: orchestrator-failure-drill  # 各局 DecisionRecord 死法栏必含协调官自身失效预演
```

### 6.2 组织权限（白名单）

- **需求局**：写注册表/缓存/需求包；派发枚举/生成/原型员（判定类派发须人确认）。不含：改假设台账裁决、改本规范。
- **测试质检局**：写证据账本/测试用例/探针队列；签发可执行化判定；授 Pre-Verified。不含：改 AC 与需求（分诊四类是唯一通道）、授 Verified。
- **阶段组织**：只写分配的闭包产物目录；最小权限；验收即解散。
- 治理链：goal-keeper → 本规范 → 各局 → 阶段组织 AOOS → 行动 → 证据 → 问责。

### 6.3 递归边界

本规范与政策/模板默认条目的修改=不可逆决策，唯一路径 goal-keeper 终审；各协调官可起草改进提案，执行属另一经批准组织。轻量通道准入为显式定义，扩条件即修规范。

## 第九章 使用手册（独立运行）

### 9.1 冷启动清单

①一个人类（愿在七触点出场，尤其 L1 与终审）；②一个 AI 会话（能读写文件、能派 fresh 子代理）；③五个文件区：注册表（md 表格）/五库缓存（判据/维度/异常/假设/依赖图，初始可空——未命中即生成是常态）/本规范/未闭合假设台账/DecisionRecord 区；④政策块直接抄 §6.1。

### 9.2 一个商业目标的完整走法

1. **进入**："按生产局处理：<商业目标一句话>"。
2. **假设受理门**：协调官出三问初答+假设台账草案（H1…Hn 按脆弱×值钱排序）→ 人终审排序。
3. **需求**：通道判定（人确认）→ 轻量（裂缝 checklist+mini 三件套）或全量（存量先测绘/探测；L0 两枚举员并行；L1 人逐项决策；L2 差异候选；L3 并排原型）→ 锁定门双签 → 人批准。
4. **设计**：三元组（闭包/合同/AOOS）→ 设计审查门（fresh 敌意）→ 不可逆签字。
5. **实现**：开发组织成军 → 六态推进（异常上浮走例外路由）。
6. **质检**：分诊四类 → 发布门（契约+灰度）→ 人授 Verified。
7. **回填**：假设台账裁决 → 固化判定（双门）→ 记账 → 解散阶段组织。
8. **震荡**：任何一级 T1/T2/T3 触发按 §5.5 处置，不向下游传染。

### 9.3 人类指南（一页）

七触点见 §5.7。三条红线：不替 AI 枚举维度（它见得多）；不让 AI 做你的 L1/L3/终审（它没有后果）；说不出要什么时进 L3（选得出比说得出可靠）。长期不在线=系统安全停机于待批，不会自行越权。

## 附录 A 敌意审查继承与本域风险

继承成军局 18 处击穿修复（判定者不得自免审/批准即登记/固化分权/政策层入变更门/自动化=会话内 checklist/对己不豁免失效预演）。本域新增：①原型偏好引导污染（原型器 constraints）；②台账事后合理化（回填必附数据锚点）；③七触点负担（L1 可授权预决策清单批量裁决，不可整体委托）；④对抗无棘轮则发散（info-gain-ledger）；⑤基准真空（relock-after-switch）；⑥双局合谋（需求局与测试局若共享上下文/人事，双签退化为单签——两局须保持组织与上下文隔离）；⑦**R-Hyrum：行为已被验证而未回写需求 → 隐性需求固化**（未验证实现被扶正为基准时，一切可观测行为含 bug 被下游依赖成"事实标准"——比基准真空更隐蔽，系统看起来正常运转）→ 回写纪律不可省（v0.1.1 增）；⑧**认知债与触点淹没**——六招推到极限即"人只按按钮"=失败形态（判断外包≠问题消失，Ghost Capability，失败发生在判断力空白处）→ 判断再生红线（不可逆亲自推演/关键抽样人亲自份额/三问先行/撤脚手架演练）＋例外分级与批量窗口防告警风暴（v0.1.2 增）。

## 附录 B 术语速查

**双签锁定**：需求局起草 AC × 测试局签发可执行化判定。**判别器无修宪权**：质检改测量自由、改需求零自由。**逃逸距离**：错误发现层−发生层。**三元组**：闭包分解+界面合同+组织设计。**探针**：以最小不可逆表面积买系统行为真信息的装置（特征测试/影子流量/回放/并行跑）。**flag 参数化**：可逆维度的运行时表示。**T1/T2/T3**：不可达/证伪/空转触发器。**基准真空**：需求与实现同时失锚的最差状态。
