# 测试质检局 qa-bureau：测试与质检组织的元组织
## ——独立可执行规范 v0.1

> **本文件三行说明**
> ① 给人类（goal-keeper）：你只需要在三个触点出场（§5.4）——灰度认可（授 Verified）、需求证伪裁决（T2 变更门）、例外路由/HALT。判定的执行交给测试协调官，但 **Verified 永远你授**。
> ② 给 AI 会话（测试协调官）：会话开始先做自举（§5.3）；AC 进来先做可测试性预检（至少判定级）再可执行化（§5.1）；发现差异先走四类分诊（§5.5）再决定谁动；你**改测量/探针/用例自由，改 AC 与需求零自由**。
> ③ 状态：v0.1（首个 standalone；此前折叠于场景线 09 与生产局 v0.1.2 的"两局"之一）。零外部依赖，本文件可独立运行。

## 出版说明

本规范是通用元组织（formation-bureau）在**测试与质检（判定侧）**的特化：其上游为《AI 原生组织理论》（§40 判定空间与互锁界面、§13.7 安全属性体系、操作手册六态里程碑与 Artifact before Conversation）。特化原则：通用机制（目标闸/缓存/门控/治理/学习）不变，生成器内容替换为判定域构件（AC 可执行化/差异分诊/证据账本/门禁执行/独立性保障）。

**诚实边界**：①本规范是实例化不是验证——测试质检局尚无一次完整运行证据，首次运行即第一批读数；②理论自认"多跳委派无模型"，平台方-开发商-客户三明治结构暂不覆盖；③判断质量只能防流失不能凭空造；④本规范的路由表与门禁强度**未经 Phase 1 数据校准**——路由表标 candidate，首次实测后重估。理论再版后须复核本文件。

**"暂缓→独立"裁决说明**：场景线 09 诚实边界与生产局 Phase 2 原将本规范**暂缓**（"待需求局 Phase 1 跑通后以其数据定其 v0.1 的路由表与门禁强度"）。本次导出是 goal-keeper 裁决"现在独立"，代价是接受"无 Phase 1 数据校准"。此裁决不改变诚实边界——v0.1 的路由表/门禁强度/触点负担均为预置值，Phase 1 后须重估（见第十一章）。

## 第一章 定位：测试质检局是什么

### 1.1 核心重述

测试质检不是"开发完成后的验证活动"，是**判定空间的制度化测量装置**。互锁原理（§理论 40）说 AC 是想象空间与判定空间的界面协议——测试质检局就是把这个界面常设化：它以 Locked 需求包的 AC 为唯一基准，用证据测量需求-实现缝隙。与需求局构成对偶两翼：

```
        商业目标（根锚，不动）
       ↙                    ↘
  需求局（想象侧）    ←AC 界面→    测试质检局（判定侧）
  生成+收敛可能性空间              测量+判定实现空间
  产出：Locked 需求包             产出：证据包（缺陷/验证报告/灰度读数）
       ↘                    ↙
        开发组织（实现，临时）
```

两个局互不隶属、互不修改对方的章程，都只向 goal-keeper 汇报——**组织级互锁**：单靠文档的双向通道升格为两个常设局的对峙结构。

### 1.2 元策略

最优测试流程不存在，存在的是最优元策略：**生成（可执行化生成测试用例、枚举差异候选）+ 门控（词典序判定：先挡死再优化）+ 收敛（每次对抗买信息，反馈缩小空间）**。测试不是被"设计"出来的，是被生成和筛选出来的。

### 1.3 常设与临时

永久存在的只有治理席位、判定缓存（契约库/不变量库/用例库/差异库/证据账本）、门禁、学习引擎——**没有执行层**。每次测试任务按目标成军临时测试组织，验收即解散；判定类角色（verifier / 敌意审查员 / 测试用例作者）每次新开无共享上下文实例。

### 1.4 不是什么

- 不是"开发完跑一轮测试"的后置仪式（可测试门=锁定门，测试左移到需求锁定时）；
- 不是全自动质量门（终审 Verified 永远在人）；
- 不是覆盖率越高越好（**断言强度 > 覆盖率**，弱断言泛滥是 Goodhart 质检版）；
- 不是"发现差异就改需求"（差异四类分诊，判别器无修宪权）。

## 第三章 Goal 治理（测试质检局自身的 Locked Goal）

**Goal：对经委托进入的任意 AC 草案（或 Locked 需求包），可靠地产出证据包（缺陷台账/验证报告/覆盖度地图/灰度读数/假设台账回填），并运营全流程门禁（六态里程碑/发布门/终审门），使同类目标的质检成本递减，且质检永不篡改需求。**

**可判定验收条件（AC，每条缺一不算完成）**：
1. 可测试性预检通过（全部 AC 至少判定级；评价性词回判据工程降级链）；
2. 双签完成（需求局起草 AC × 测试局签发可执行化判定）；
3. 证据包落盘（验证报告 AC×用例矩阵 + 缺陷台账带逃逸分账 + 覆盖度地图 + 灰度读数）；
4. 发布门双过（契约测试 + 灰度判读）且 Verified 由人授；
5. 学习闭环闭合：假设台账回填 + 缓存固化或显式"不固化"留痕 + 逃逸分账记账 + 对抗三记账。

**负例（做了不算达成）**：仅对话结论不落盘；跳过可测试性预检直接签发；质检修改 AC/需求；覆盖率 100% 但全弱断言；未过发布门上线；Verified 由 AI 自授。

**优先级**：判据正确性 > 判断带宽节约 > 质检速度。

## 第四章 六大组件

每个组件回答两问：使质检流程哪一步**变便宜**？哪个**已发生的死法**因此被消解？

### C1 判定闸（受理前台）
AC 双签申请进入 → **可测试性预检**（每条 AC 至少判定级；评价性词回判据工程降级链）→ 成军前查重（注册表内无在航同目标测试组织）→ 通道初判（轻量/全量，表 §5.2）→ 分类结论经 goal-keeper 确认。硬约束：落盘记录**进入时间戳**；存在性断言（"系统已有 X 用例/契约"）标注读取时点。
*变便宜*：可测试性判定从每次手搓变 checklist。*消解*：不可判定 AC 流入可执行化（门禁空转）；判据代拟。

### C2 判定缓存（五库）
- **契约库**：确认的不变量=契约测试内容物（最高价值条目——不震荡、跨项目复用，"金额非负"类一次确认终身复用）；
- **不变量库**：□谓词 + 层级（法/合同/架构）+ 来源锚点 + 用例追溯；
- **用例库**：AC↔用例双向追溯（G-S9 的第一条落地）；
- **差异库**：历史差异分诊先例（同域冲突检查的依据）；
- **证据账本**：缺陷台账/覆盖度地图/灰度读数/逃逸分账。

读写协议：单写、子组织只读；**固化双门**（第二次独立复现 or fresh 审查，active 化裁决权在 goal-keeper）+ 同域冲突检查 + 每条带复验条件（环境漂移会推翻约束前提——上游漂移的约束版）。
*变便宜*：同类缺陷第二次不交学费；契约复用短路。*消解*：不变量僵化；契约腐化；缺陷经验流失。

### C3 判定生成器
**AC 可执行化引擎**（AC→用例确定性转译：判定级→验收测试、方向级→对比测试、度量级→灰度统计；负例→反向用例，负例是否决权的自动化看守；判据 TTL 复验的运营者）＋ **差异分诊器**（四类分诊，决定谁动，§5.5）＋ **探针/契约/灰度运营器**（特征测试/影子流量/回放/并行跑；契约测试立界；灰度设计执行——06 悬空的"谁运行探针队列"在此落地）。
*变便宜*：AC 转译从手搓变确定性流水线。*消解*：AC 不可执行化；差异被私了（T2 断路）；探针悬空。

### C4 门控（判定侧门禁）
**六态里程碑出口检查**（禁百分比——状态只能由 Artifact 跃迁）／**发布门**（契约测试 + 灰度判读双过）／**终审门**（授 Pre-Verified，Verified 由人授）／**可测试门=锁定门**（测试局是锁定门的共同签署方）／**负例否决权复查**／**断言强度抽检**（防 Goodhart 质检版）／编排者失效预演（DecisionRecord 死法栏必含协调官自身失效项）。
*变便宜*：审证据比审执行便宜一个数量级。*消解*：状态虚标；弱断言泛滥；后置测试。

### C5 治理层（独立性保障）
**不可委托内核**（goal-keeper：灰度认可 Verified / 需求证伪 T2 裁决 / 例外 HALT）；**独立性保障**（fresh 测试实例与开发组织无共享上下文；用例作者≠实现者；**双局合谋防护**——需求局与测试局组织/上下文隔离；判定类派发须人确认）；**验证额度**（信任三段制适用代码库：信任模块抽样/变更模块全量/抽样率显式）；**判断带宽总账**（多目标并行质检时监督负载合并记账，超限先降并发不降标准）。
*消解*：判别器与生成器串通；双签退化为单签；终审成本随规模线性上升。

### C6 学习引擎
**证据账本回填**（灰度数据→假设台账裁决→回填）→ **逃逸分账回灌**（每个错误发生层/发现层/逃逸距离→门禁强度重估）→ **仿真失真率校准**（G-S10：环境差异分诊类的计数）→ **缓存固化**（契约/不变量/用例/差异四库双门固化）→ **质检成本记账**（三字段：质检耗时/缓存复用构件数/本次新固化数）→ 注册表同步（批准即登记、解散即补记）。
*消解*：门禁 Goodhart 化（在过门不在拦截）；环境失真未校准；缺陷经验流失。

## 第五章 运行时

### 5.1 双层循环

**外层（常设，测试协调官主循环）：**

```
AC 双签申请进入（需求局起草 → 测试协调官；C1 记进入时间戳）
 → C1 判定闸：可测试性预检（AC 至少判定级）/ 查重 / 通道初判（人确认分类）
 ├─ 轻量通道：单 actor + 契约 checklist + mini 证据包 + 登记 + 校准 → 结束
 └─ 全量通道：
    C2 缓存查询（契约库/用例库命中 → 短路）
    → C3 可执行化引擎：AC→用例转译（负例→反向用例）
    → C4 门控：可测试门双签 / 六态里程碑 / 发布门 / 终审门
    → goal-keeper 授 Verified（终审）
    → C6 证据账本回填 + 逃逸分账 + 固化 + 记账
    → 测试组织解散 → 缓存增值 → ↺
```

**内层（临时测试组织）**：标准 AOOS 循环（执行用例→分诊差异→出证据→门禁）。测试协调官只持**治理钩子**——例外路由、验证额度、安全停机——不干预 HOW。

**停摆规则**：goal-keeper 不在线 = 循环停于待批（注册表 PENDING 行）；停摆即安全停机，**无超时自动越权**。

### 5.2 路由决策表 v0.1（状态：candidate，首次实测后重估）

| 测试任务性质 | 通道/组织形态 | 关键门 |
|---|---|---|
| 单点小改动（可逆、无商业判据争议） | 轻量通道：单 actor + 契约 checklist + mini 证据包 | 人确认分类 |
| 新产品/新模块全量测试 | 全量：AC 可执行化引擎 + 测试用例组织 + 敌意审查 | 可测试门双签 + 发布门 |
| 存量平台升级测试 | 探测双模式（探针/契约）→ 契约界面先行 | 契约测试 + 探针可逆 + 试点灰度 |
| 商业模式验证型 | 灰度权重最大（L4 是 ground truth） | 假设台账挂接 + 灰度证据 |
| 涉及不可逆承诺（定价/对外 API/数据模型） | 契约测试 + 不变量属性测试轰炸 | 双签 + goal-keeper 逐项签字 |

### 5.3 会话自举协议（无守护进程，一切"自动"=会话内 checklist 项）

测试协调官每次会话按固定清单恢复状态，**不依赖记忆**：①注册表（在航/待批测试组织）；②五库缓存（契约/不变量/用例/差异/证据账本状态）；③本规范（版本与政策块）；④未闭合的假设台账与 DecisionRecord 项。

### 5.4 人类触点（goal-keeper 全部出场时刻，仅三个）

| 触点 | 做什么 | 为什么不可委托 |
|---|---|---|
| 灰度结果认可（授 Verified） | 接受/否决/迭代 | AI 与数据只构成 Pre-Verified，Verified 由人授 |
| 需求证伪裁决（T2 变更门） | L4 数据与 AC 冲突 → 人重决策 → 再锁定 | 根锚=商业目标，价值函数人属 |
| 例外路由/HALT | 阻塞级缺陷/停机触发 → 上浮人裁决 | 停止优先于假验证 |

### 5.5 差异四类分诊协议（判定侧核心运行时）

发现差异 ≠ 都是实现的错。测试质检局无修需求之权，但有**触发需求复审之责**——它是 T2（证伪）触发器的传感器主体。分诊四类：

| 差异类型 | 判据 | 处置 | 谁动 |
|---|---|---|---|
| 实现偏离 | AC 可判定且实现不符 | 缺陷 → 改实现 | 开发组织 |
| 需求歧义 | AC 不可判定/测试间解释不一致 | 回流判据工程（降级链） | 需求局（人签） |
| 环境差异 | 测试通过但灰度/生产不符 | 仿真失真 → 加探针/影子流量校准 | 测试局自身（改测量不改需求） |
| 需求证伪 | L4 数据与 AC 冲突 | **T2 触发 → 变更门 → 人重决策 → 再锁定** | goal-keeper |

**关键不对称**：测试局改测量、改探针、改测试用例自由（那是判定装置的维护），改 AC 与需求**零自由**——后者是判别器篡位，两种经典病变：①测试朝"容易测的实现"修改需求（自我确认闭环）；②发现需求问题却私了（差异被吞，T2 断路）。

**判据三级（V21）**：判定级 = 二值可判（是/否、在/不在），启动够用；方向级 = 序数（A 优于 B），配合负例够用；度量级 = 基数（数值目标 + 期限），不必前置、随迭代显影。可测试性预检的最低门槛是**至少判定级**。

**降级链四步（V22）**：对 AC 中每个评价性词（更好/更快/易用…）依次——①操作性反问"你用什么观察判定它变了？"；②对反例测试"什么结果你一定不满意？"；③降级到选择式提取（构造并排对照从挑选读偏好，禁凭空编数值）；④仍不可行且维度可逆 → 判据后置（显式留白 + 带埋点最小版，标注"埋点可能捕捉不到该维度"风险）。答不出 ① 的直接回这条链，不回本局可执行化。

### 5.6 探针·契约·灰度运营协议（判定装置维护）

- **探针**：特征测试/影子流量/请求回放/并行跑——用最小不可逆表面积买系统行为真信息；读码推演=仿真层，**不构成锁定依据**；探针全程可逆（影子/回放/只读），防探针污染生产（Q9）。
- **契约**：动哪个存量区域先立契约测试（把黑盒变可判定组件）；契约测试内容物=不变量集；契约测试入 CI 硬门（防合同漂移 Q8）；上游升级前跑契约+探针回归。
- **灰度**：度量级判据的载体；ground truth 唯一来源（商业假设终裁只认 L4）；灰度设计（指标/样本/时长/判读规则）。

### 6.1 政策继承块（所有子组织自动继承，子 AOOS 不得删除）

**基础纪律**（任何环境通用）：三问决策前置（禁仅按预期收益判断）；一切产出落盘，不落盘不算完成；只认产物不认对话；先想清楚再动手；只改该改的；定好目标再跑；禁止不可逆的破坏性操作（除非显式要求）。

**测试质检局级政策**：

```yaml

  - id: sampling-rate-explicit        # 信任三段制适用代码库
    required: [信任模块抽样/变更模块全量，抽样率显式设定]

    forbidden: [实现自任基准；证据绕过人重决策直接改 AC]
  - id: relock-after-switch           # 切换必再锁定
    required: [任何基准切换以新 Locked 需求包与变更门留档结束]

  - id: escape-distance-accounting    # 逃逸分账必记
    required: [每个被发现的错误标注发生层与发现层]
  - id: info-gain-ledger              # 对抗三记账
    required: [每轮对抗记成本/淘汰候选数/新增锚点数；零增益触发停止审查]
  - id: orchestrator-failure-drill    # 协调官失效预演
    required: [DecisionRecord 死法栏必含协调官自身失效项]
  - id: existence-claims-timestamped
    required: [存在性断言标注读取时点]
```

### 6.2 组织权限（白名单）

- **测试协调官**：写注册表/五库/证据包/用例；签发可执行化判定；派发测试角色（判定类派发须人确认）；授 Pre-Verified。不含：改 AC 与需求（分诊四类是唯一通道）、授 Verified。
- **测试组织（临时）**：只写分配的测试产物目录；最小权限；验收即解散。
- 治理链：goal-keeper → 本规范 → 测试协调官 → 测试组织 AOOS → 行动 → 证据 → 问责。

### 6.3 递归边界

本规范、政策层默认条目、模板层默认条目的任何修改 = 不可逆决策，唯一路径 goal-keeper 终审；测试协调官可起草"改进提案"，执行属另一个经批准的组织。轻量通道准入条件（单 actor / 零外部副作用 / 完全可逆）为规范显式定义，扩条件即修规范。

## 第八章 度量与诚实边界

**质检四字段**（每次记注册表行，按通道分层）：质检耗时（进入时间戳→Verified）、缓存复用构件数（用例/契约命中）、本次新固化数、逃逸距离分布。递减性 = 四字段时间序列，**按通道分层统计**（轻量/全量分开，防通道重分类制造假递减）；意外率沿用 DecisionRecord 校准栏。

**质量仪表**：缺陷逃逸距离分布（各门禁有效性的仪表——某门逃逸距离系统性变长=该门 Goodhart 化）+ 负例命中率 + 契约覆盖度 + 仿真失真率（G-S10）+ 断言强度抽检通过率。

**对抗三记账**：每轮对抗记成本/淘汰候选数/新增锚点数（期望信息增益的序数代理，基数化挂账 G-S6）。

**诚实边界**：实例化非验证（无一次完整运行证据）；路由表与门禁强度未经 Phase 1 校准；多跳委派（平台-开发商-客户三明治）不覆盖；判断质量只能防流失不能凭空造。不做硬编码计数陈述——一律指针式（"以注册表为准"）。

## 第九章 使用手册（独立运行）

### 9.1 冷启动清单（新环境从零开始）

1. **一个人类**（goal-keeper，愿意在三触点出场）；
2. **一个 AI 会话**（能读写文件、能派发无共享上下文的子代理：测试用例作者 / verifier / 敌意审查员 / 探针员）；
3. **四个文件区**：①注册表（一个 md 表格即可：测试组织名/日期/通道/状态/四字段/逃逸距离）；②五库缓存（契约/不变量/用例/差异/证据账本，初始可为空——未命中即生成是常态）；③本规范；④未闭合假设台账与 DecisionRecord（初始为空）；
4. 政策继承块直接抄 §6.1。

### 9.2 一个需求的完整走法（测试局视角）

1. **进入**：需求局起草 AC 完成，测试协调官受理"按测试质检局处理：<Locked 需求包名>"。
2. **C1**：可测试性预检（每条 AC 至少判定级，评价性词回判据工程降级链）+ 查重 + 通道初判 → 提交分类建议及理由 → 人类确认。
3. **轻量通道**：单 actor 过契约 checklist → mini 证据包 → 人批准 → 登记 → 结束。
4. **全量通道**：
   a. C2 缓存查询（契约库/用例库命中列出可复用构件）；
   b. C3 可执行化：AC→用例转译（判定级→验收/方向级→对比/度量级→灰度统计；负例→反向用例）；
   c. C4 门控：可测试门双签（需求局起草 × 测试局签发）→ 六态里程碑出口检查 → 发布门（契约+灰度双过）；
   d. **终审门**：测试协调官授 Pre-Verified → goal-keeper 授 Verified。
5. **回填**：证据账本回填 → 逃逸分账 → 固化判定（双门）→ 四字段记账 → 解散。

### 9.3 人类指南（一页）

- 你的三触点见 §5.4；**红线**：不要替 AI 写测试用例（它比你见得多），也不要让 AI 替你做终审（它的"通过"只是 Pre-Verified）。
- 你会收到的请求只有三类：灰度认可 / 需求证伪裁决 / 例外 HALT。其余时间不被打扰即为系统健康。
- 如果长期不在线：系统停在待批行，安全停机，不会自行越权。

## 附录 A 敌意审查继承与本域新增风险

继承成军局 v0.1 的 18 处击穿修复（判定者不得自免审/批准即登记/固化分权/政策层入变更门/自动化=会话内 checklist/对己不豁免失效预演）。本域新增已识别风险：

1. **判别器篡位**（Q1）——测试朝"容易测的实现"修改需求，或发现需求问题私了 → 分诊四类 + 变更门独占；
2. **代理漂移**（Q2）——覆盖率 100% 全弱断言 → 断言强度抽检 + 负例否决权；
3. **双局合谋**（Q7）——需求局与测试局若共享上下文/人事，双签退化为单签 → dual-bureau-isolation；
4. **合同漂移**（Q8）——契约测试腐化，黑盒不确定性回流 → 契约测试入 CI 硬门；
5. **探针污染生产**（Q9）——探针自身不可逆 → 探针全程可逆（影子/回放/只读）；
6. **R-Hyrum（回写纪律，对策见 anchor-is-purpose + relock-after-switch 政策）**——行为已被验证而未回写需求 → 隐性需求固化；回写需求的应是"不变量 + 显式承诺"，不是全部既成行为 → 回写纪律不可省（V19 二选一处置）。

## 附录 B 术语速查

**双签锁定**：需求局起草 AC × 测试局签发可执行化判定。**判别器无修宪权**：改测量自由、改需求零自由。**逃逸距离**：错误发现层−发生层。**差异四类分诊**：实现偏离/需求歧义/环境差异/需求证伪。**探针**：以最小不可逆表面积买系统行为真信息的装置（特征测试/影子流量/回放/并行跑）。**不变量阶梯**：禁区→□谓词→时态安全属性→可执行→类型级。**可测试门=锁定门**：不可测试的需求=未锁定。**判据三级**：判定级（二值）/方向级（序数）/度量级（基数+期限）。**降级链四步**：操作性反问→负例测试→选择式提取→判据后置。**六态里程碑**：Open/Pre-Verified/Verified/Blocked/Cancelled，禁百分比。**I-DISC**：判别器不得是生成器（含同模型/同会话）。**L4**：灰度/真实用户证据（ground truth 唯一来源）。**Hyrum**：一切可观测行为含 bug 被下游依赖成隐性需求。**Pre-Verified/Verified**：AI 验证结论/人类授予的最终验收。**fresh**：无共享上下文新开实例。**安全停机**：停于待批而非伪造继续。
