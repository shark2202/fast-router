# fast-router 使用手册

> **你是谁**：你用 AI agent 干活，不想为"这个任务用哪个模型"操心。
> **你不需要**：读配置、管进程——那是部署与运维的事（见姊妹手册）。

---

## 1. 一分钟接入

fast-router 就是一个 OpenAI 兼容端点（外加 Anthropic 协议）：

```bash
# OpenAI 系客户端（codex / 大多数工具）
export OPENAI_BASE_URL=http://127.0.0.1:8080/v1
export OPENAI_API_KEY=<网关侧约定即可，可为任意值>

# Claude 系客户端（claude code 等）
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
```

协议自动双向转换：OpenAI 客户端可以打到 Anthropic 上游，反之亦然（含流式与工具调用）。

## 2. 可用"模型"

| 填法 | 行为 |
|---|---|
| **`fast-router`（推荐，固定名）** | **智能路由**：网关本地评分选最合适的真实模型——你永远不需要知道后端有哪些模型 |
| `上游名/模型id`（如 `deepseek/deepseek-chat`） | **强制指定**，跳过智能路由 |
| 不确定有哪些上游 | `curl localhost:8080/v1/models` 或问运维要上游清单 |

## 3. 你会观察到的现象（都是正常的）

| 现象 | 原因 | 说明 |
|---|---|---|
| 会话第一条请求慢 2~3 秒 | 网关在做任务分类（本地小模型） | 之后同任务续轮毫秒级 |
| 同一会话中途换了模型 | 后台精修层覆写了更准的路由 | 目的：更准，不影响上下文 |
| 偶发某条请求明显更慢且答案更全面 | 低置信任务自动升级了**多模型委员会**（MoA） | 多个模型答案被聚合成一条，你只见最终答案 |
| 某上游连续报错后不再被使用 | 网关检测到该上游不健康，自动切流 | 运维会收到判据记录 |
| 长文本请求没走某小窗口模型 | 上下文保护：该模型装不下 | 自动换大窗口模型 |

## 4. 隐私须知（重要）

启用智能路由的网关会在本地记录**请求文本片段**用于评分与改进模型（`data/train_log.jsonl`）。若你的任务涉密，接入前与运维确认该实例的数据策略。

## 5. 常见问题

**Q：首条请求能更快吗？**
运维侧可换更小的评分模型（首评 ~0.3s 级）或关闭智能路由（纯代理，0ms 但盲路由）。

**Q：我想临时固定用一个模型？**
请求里 `model` 填 `上游名/模型id` 即可，该请求跳过一切智能逻辑。

**Q：流式（SSE）支持吗？**
支持，`stream:true` 原样透传（MoA 升级的请求最终也以流式返回）。

**Q：工具调用（function calling）支持吗？**
支持，且工具调用在双向协议间正确转换（tool_calls ↔ tool_use）。工具调用请求不会被升级到 MoA（多模型工具调用聚合不可靠，网关自动绕开）。
