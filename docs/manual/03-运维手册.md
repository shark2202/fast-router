# fast-router 运维手册

> **你是谁**：守着运行中的实例，看健康、管模型、值班排障。
> **入口**：管理界面 `http://<host>:8080/admin`；观测走 `/api/*`；排障先看 §4 矩阵。

---

## 1. 日常观测

### 1.1 观测端点速查

| 端点 | 看什么 | 频率建议 |
|---|---|---|
| `GET /api/verdicts` | 最近 200 条路由判据（via/task/outcome/status） | 实时排障 |
| `GET /api/measured` | 实测矩阵：task×model ok_rate + 空层 | 每日 |
| `GET /api/config` | 当前生效配置 | 变更后 |
| 日志关键字 | 见 §1.2 | 常态 |

### 1.2 日志关键字 → 含义

| 关键字 | 含义 | 需要动作吗 |
|---|---|---|
| `[route]` | 一次选模决策（jev 选择了什么/挡死几个/选了谁） | 否 |
| `[route-fast] …failed` | 快评层异常，已自动回退 hint | 连续出现→查 fast 模型 |
| `[route-async] backfilled` | 精修层完成覆写 | 否 |
| `[moa] escalated` | 委员会升级（含 refs 数/耗时） | 监控频率（成本） |
| `[hot-reload]` | 评分模型热换 | 变更留痕 |
| `warn: fast-tier model failed to load` | 启动时快评层加载失败 | 立即处理 |

### 1.3 数据 → 动作对照

| 看到 | 含义 | 动作 |
|---|---|---|
| measured 里某 (task,model) ok_rate 低 | 该组合实际差 | 无需手动——L1 自动降权；长期低位考虑从 registry 剔除 |
| empty_layers 常年有某类 | 任务类型从未被路由 | 评估裁撤类目（改 SeedTaskTypes 需重验） |
| verdicts 连续 upstream_error/connect_error | 上游故障/配额 | 健康机制自动切流；持续则查该上游账号 |
| `[moa] escalated` 频率突增 | 评分器对流量分布变生疏（或流量变难） | 正常自适应；成本敏感则调高 min_confidence |
| train_log 里 fast 层平均置信度持续走低 | 评分器漂移 | 触发一次重训周期（§3） |

## 2. 模型生命周期

### 2.1 下载

管理界面 → Models：选模型（modelscope 源）→ 异步下载 → 配置 `model.fast_path` 指向。

### 2.2 热更新（不重启）

```bash
curl -X POST localhost:8080/api/model/reload -H 'Content-Type: application/json' \
  -d '{"fast_path": "models/router-v3.gguf"}'
# → {"ok":true,"load_ms":…}  旧模型在宽限期后自动释放
```

### 2.3 回滚

保留上一版 GGUF 文件，`/api/model/reload` 指回即可（秒级）。**建议常驻保留最近两版。**

## 3. 自训练周期（进阶，按需执行）

```bash
# 一键（内置回归门，门不过自动保留旧模型）：
scripts/distill/auto_retrain.sh
# 前置：data/train_log.jsonl 里 slow 层（教师）样本增量 ≥200（MIN_NEW 可调）
```

**回归门纪律（不可跳过）**：任何重训产物必须先过冻结基准（30 样本 P1 ≥ 当前部署值）。历史实测：跳门上线曾致路由质量 73.3%→46.7%。

周期产物归档：`/tmp/fr-retrain/`（训练日志/中间权重）+ `data/.last_gate`（当前门值）。

## 4. 故障排查矩阵（按症状索引）

| # | 症状 | 先查 | 常见原因 → 处置 |
|---|---|---|---|
| 1 | 全部请求 502 | verdicts 是否全是 connect_error | base_url/key 错 → `/api/upstream/test` 验证；provider 故障等恢复 |
| 2 | 上游 4xx 余额/鉴权 | 响应体错误码 | key 失效/欠费 → 更换；健康切流已自动兜底 |
| 3 | 首请求秒级慢 | 是否配了 fast_path | 正常（分类耗时 2~3s）；不可接受→换更小模型或降 A 档 |
| 4 | 首请求 38s+ 阻塞 | `async_score` 是否 false；启动日志 fast-tier 告警 | 改 true；修 fast 模型加载 |
| 5 | 评分全错/报多 token | 模型词表 | 内置 yes→Yes→是 回退；自定义模型确认肯定词是单 token |
| 6 | MoA 后答案变差 | `[moa]` 日志 refs 数 | refs=0 正常回退；聚合器太弱→换强聚合模型 |
| 7 | 启动 dlopen 失败 | `DYLD/LD_LIBRARY_PATH` | 指向 libllama 目录；核对包完整性 |
| 8 | `fr_load returned nil` | 模型路径/内存 | 路径错→改；9B 需 ~7GB 空闲内存 |
| 9 | 长请求被跳过某模型 | — | 上下文门正常保护；换大窗口模型或精简请求 |
| 10 | 内存缓慢增长 | 热换次数 | 已知：宽限期释放正常；异常增长→重启（无状态损失，除进行中请求） |

## 5. 数据管理

| 文件 | 内容 | 保留策略 |
|---|---|---|
| `data/verdicts.jsonl` | 判据（校准+健康数据源） | 长期保留；体积敏感可截旧（保留近万条即可） |
| `data/train_log.jsonl` | 评分记录**含请求原文** | 按隐私策略：敏感场景定期清理或停用自训练；重训周期消费后可归档 |
| `fast-router.json` | 唯一配置真值 | 变更前备份（回滚依据） |

## 6. 应急预案

| 场景 | 动作 |
|---|---|
| 评分模型疑似劣化（用户反馈路由变差） | 热换回上一版（§2.3）；比对 verdicts 前后 ok_rate |
| 网关本身异常（崩溃/挂起） | 重启（无状态，秒级恢复；进行中请求丢失） |
| 上游全挂 | 网关无法替代上游；通知使用者切备用端点 |
| MoA 成本失控 | `POST /api/config` 调高 `moa.min_confidence` 或置 `enabled:false`（热生效） |
| 误配导致大规模错路由 | 恢复配置备份 + 重启；verdicts 可事后审计影响面 |

## 7. 已知限制（值班需知）

1. 后台评分串行（单 context 互斥）——高并发新任务的首评可能排队
2. MoA 聚合器中途失败透传给客户端（同单模型行为，无自动重试）
3. Windows 实例评分功能受限（建议 A 档运行）
4. 评分质量数字（73.3%）来自 30 样本基准，生产分布会有偏移——以 verdicts 实测为准
