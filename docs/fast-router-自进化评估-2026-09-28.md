# 自训练/自进化模式可行性评估

## 结论先行（三行）

> ① **可以，且已建成四分之三的地基**：C7 判据在采、Measured 权重接口预留、Select 加权公式就绪——第一层"路由策略自进化"今天就能闭环。
> ② 四层能力递进：L1 路由权重自校准（纯统计，零风险）→ L2 任务类目自演化（C9，需复核门）→ L3 打分 prompt 自优化（P1 敏感，慎动）→ L4 模型自训练/蒸馏（真·自训练，本机硬件不可行，留作离线管线）。
> ③ 核心风险不是技术是**反馈偏置**（被选中者才有数据→自我强化）与**污染信号**（429/断连≠模型差）——L1 用最小样本门+信号过滤压制，探索机制记为后续选项。

## 二、方法

按维度/死法/可逆性逐层评估；实现裁决只取"今天可闭环且可回退"的最小增量。

## 三、四层能力评估

### L1 路由策略自校准（verdict → measured 权重）——**本轮实现**

- **机制**：C7 判据按 (task_code, model_id) 聚合 ok_rate → 写入 measured map → `Select` 从"最便宜优先"切换为"实测通过率加权"。用得越多路由越准。
- **维度**：路由 ok_rate 随使用提升；不碰 P1（只在 C4 幸存者内部重排）；不碰模型。
- **死法**：①反馈偏置（未选中模型无数据→永远冷启动）②小样本噪声（3 次失误就拉黑）③信号污染（connect_error/429 不是模型的错）④自我强化环（好→多选→更多好数据）。
- **对策**：最小样本门（n<5 不生效，机制天然存在：measuredRate 返回 nil 即回退冷启动）；connect_error 剔除；429 污染记为局限；探索 epsilon 记为后续选项（不现在做——能简单就别复杂）。
- **可逆性**：**完美**——measured 层是纯计算数据，不写用户 registry 配置；清空 verdicts.jsonl 即完全回退。
- **成本**：~百行 Go，无新依赖。

### L2 任务类目自演化（C9）——**接口已有，留复核门**

- 空层检测已在 `/api/measured` 输出（zero-decision 任务类型清单）。增删任务类型=改 SeedTaskTypes+registry，影响 P1 全链——按设计共识必须过"统计复核+人工门"。半自动：系统提案，人批准。
- 死法：类目漂移破坏与历史判据的可比性。可逆性：中（带版本回滚，设计已要求）。

### L3 打分 prompt 自优化——**P1 敏感，慎动**

- 用 miss 分析（verdict 失败样本的 task_code 分布）调 criteria 描述。模板/prompt 是 P1 最大因子（知识沉淀 L-009/011 的教训）——自动改 prompt=自动动 P1。若做，必须冻结样本集回归门。

### L4 模型自训练/蒸馏——**方向成立，本机不可行**

- 数据闭环成立：9B 后台评分（73.3%）作教师标签 + verdict 作奖励信号 → 蒸馏 0.5B fast tier（甚至 laya 式分类头）→ fast tier 质量逼近 73.3% 且首评 3.9s→亚秒。
- 死法：①本机无 GPU（Intel CPU 训练不现实）②训练需 PyTorch 基建=打破"无 Python 分发"不变量（训练可离线、推理保持进程内，但工程量大）③过拟合 30 样本级任务分布。
- 裁决：**留作离线管线方向**（fast tier 换 2B/3B 量化模型是更便宜的中间步——MiniCPM5-2B P1=43.3%@污染期，干净模板复测优先）。

## 四、局限

1. L1 的 ok 信号是代理指标（上游 2xx≠任务完成质量）；真判据（编译/测试通过）需客户端回传，接口未定。
2. verdict 样本量门槛（5）是拍的，需数据积累后校准。
3. 反馈偏置只做了压制未做探索；多 upstream 对称部署时问题更大。

## 五、结论

**自进化=是，分层交付：L1 本轮闭环（纯统计路由自校准，完美可逆）；L2 半自动（提案+人审）；L3/L4 方向成立但受 P1 敏感性与本机硬件约束，列为后续。** L1 落地后，fast-router 成为"越用越准"的系统——这正是设计共识 AC8-AC9 的最小完整实现。
