# MoA 深度研究

## 结论先行（三行）

> ① MoA 命题（Together AI/Duke/Stanford，AlpacaEval 2.0 上开源组合 65.1% 超 GPT-4 Omni 57.5%）与 fast-router 的深挖发现**意外互证**：我们实测的 64M/9B 错误集几乎不相交（并集上限 ~96.7%）正是"多样性>单强"机制在**分类层**的显现——同一原理在生成层（论文）与路由层（我们）各自被独立观察到。
> ② 路由（System-1 选一个）与 MoA（全体协作聚合）不是竞争是**谱系两端**；fast-router 天然握有中间态的钥匙——scorer 的 confidence 字段就是"何时升级到 MoA"的门控信号。
> ③ 对 fast-router 最务实的落点是 C-017：**置信度门控的 MoA 升级路径**（低置信任务 fan-out 多上游 + 聚合上游），且 Hermes 的三条工程决策可直接照抄。

## 三、发现

### 3.1 论文核心（生成层证据）

| 要素 | 内容 |
|---|---|
| 架构 | 分层：L 层各含多个 agent，每个 agent 以**前一层全部输出**为辅助信息生成响应；末层输出即最终答案 |
| 角色分职 | **Proposers**：擅长生成"有用参考"——自身独立分数未必高，但提供多样视角；**Aggregators**：擅长把他人（可能更弱的）输出合成单一高质量答案——"吸收弱输入仍保质量"是 aggregator 的定义性能力 |
| 结果 | 纯开源 LLM 组合在 AlpacaEval 2.0 达 65.1%（GPT-4 Omni 57.5%）、MT-Bench/FLASK 同样领先 |
| 机制解释 | 不同模型的错误/偏好分布不同 → 互补性可被聚合层收割 |

### 3.2 Hermes MoA 2.0 的工程化（实践层）

| 决策 | 细节 | 借鉴价值 |
|---|---|---|
| 预设配置 | `reference_models[] + aggregator + 温度`三段式 YAML | fast-router 若做 MoA 模式，config 结构可直接类比 |
| **温度不对称** | proposer 0.6（多样性）/ aggregator 0.4（稳定性） | 直接照抄 |
| **禁套娃** | aggregator 不能再指向另一个 MoA 规则（递归保护防会议瘫痪） | 直接照抄（网关编排同样需要） |
| **/moa 一次性** | 按次启用、用完自动还原单模型（成本意识） | 对应"选择性升级"而非常开 |
| MoA≠MoE 澄清 | MoE=单模型内部专家路由；MoA=多独立模型外部协作 | 术语边界 |

### 3.3 与 fast-router 的交汇点（本研究核心产出）

**① 意外互证——同一机制在两层独立显现**：
- 论文（生成层）：多模型输出聚合 > 任何单模型（AlpacaEval 实证）
- 本仓（分类层）：64M 与 9B 打分器错误集几乎不相交（30 中仅 1 共同错，并集正确上限 ~96.7% vs 各自 73.3%）——深挖审计 `docs/自训练证据链深挖-2026-09-28.md` §2.1
- 两者互为对方的独立佐证：**互补性是模型多样性的一般性质，不限于生成任务**。这直接强化了 C-016（分歧仲裁）的预期价值。

**② 谱系定位——路由与聚合互补而非竞争**：

```
成本/延迟谱系：
 单模型直连 ──── 路由选一(fast-router 现状) ──── 【门控升级点】 ──── MoA 全体协作
   最便宜            System-1 秒级决策                scorer conf < θ        N×成本，最高质量
```
fast-router 的 scorer 已输出 confidence 字段（train_log 在采）——**门控信号现成**。

**③ verdict 系统回答"MoA 值不值"**：哪些任务类型单模型 ok_rate 低到值得 N 倍成本上 MoA——正是 C7 measured matrix 在积累的数据。MoA 模式的开启应当是**按任务类型学出来的**，不是全局开关。

**④ 诚实边界**：
- 论文证据在开放生成任务（对话/指令跟随）；**agent 工具调用场景未证实**——N 个模型的 tool_calls 如何聚合是非平凡问题（聚合器需合并结构化输出，多样性反而可能有害）
- 知乎文是产品教程，非独立评测
- N× 成本与高频 agent 场景（用户核心诉求）直接冲突——MoA 只能作为低频升级路径，不能做默认

## 四、对 fast-router 的落地候选

**C-017：置信度门控 MoA 升级路径**（新增 candidate）
- 触发：scorer confidence < θ（或 C-016 的双评分器分歧）
- 动作：该请求 fan-out 到 N 个参考上游（高温）+ 1 个聚合上游（低温），聚合响应返回
- 现有基建复用：多 upstream 配置 ✓、schema 双向转换 ✓、verdict 记录 ✓；缺 fan-out/聚合编排（gateway 新增 ~200 行）
- 工程约束照抄 Hermes：禁套娃、按次启用、任务类型级开关（verdict 数据驱动）
- 边界：工具调用请求暂不升级 MoA（聚合未证实），先只对纯文本任务开放

## 五、局限

1. 论文只读了前 5 页核心（架构/角色/主结果）；成本-性能权衡的完整曲线未摘录。
2. Hermes 为闭源服务，其 MoA 2.0 的聚合提示词与调度细节不可见，工程借鉴限于配置范式层面。
3. C-017 的收益预估依赖"任务类型 × MoA 提升"数据，当前为零——需先有 verdicts 积累。

## 六、结论

MoA 论文与 fast-router 的深挖发现构成了跨层互证：**模型多样性带来的互补性是可以被系统性收割的一般资源**——在生成层靠聚合（MoA），在路由层靠仲裁（C-016），在升级决策上靠置信度门控（C-017）。fast-router 不需要变成 MoA，但应该把 MoA 纳入其路由谱系的"高端出口"：路由器决定何时便宜地选一个，何时昂贵地请委员会。这正是"路由"这个词的完整含义。
